# SQLite FTS5 Full-Text Search Tokenizers and BM25 Ranking

## Summary

本文详细解析了 [[entities/drizzle-sqlite-store]] 底层所使用的 SQLite
FTS5（Full-Text Search 5）全文检索模块的索引机理、分词器选择策略与 Okapi BM25
相关性排序算法。

SQLite FTS5 将文本切分为词元（Token）并维护倒排索引。文章对比了两大核心分词器：

- `porter` 分词器基于词干还原算法，适合自然语言、文章与便签内容的检索；
- `trigram` 分词器按 3
  字符重叠序列分解，能够实现无前缀通配符开销的任意子串匹配（加速
  `LIKE %pattern%`），并原生适应 CJK 语系与代码符号。

在打分排序方面，内置的 `bm25()`
函数结合词频（TF）、逆文档频率（IDF）与文档长度惩罚计算相关性，并遵循 SQLite
的负数得分惯例（越小/越负代表匹配度越高），同时支持对标题与正文列应用不同的权重加权。

## Key Takeaways

- **分词器语义隔离**：文本搜索首选 `porter unicode61`，子串代码与中日韩首选
  `trigram`；
- **BM25 负数得分规范**：SQLite FTS5 `bm25()` 返回负数，排序必须使用
  `ORDER BY bm25(...) ASC` 或 `ORDER BY rank`；
- **列级权重配置**：支持对不同字段（如标题 5.0，正文
  1.0）进行加权打分，大幅提升搜索召回准确率。
