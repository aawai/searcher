# Security and permissions

原文：[Deno 官方文档](https://docs.deno.com/runtime/fundamentals/security/)。证据：[不可变提取文本](../../raw/sources/SRC-2026-10-26-002/extracted.md)，正文第 222–399 行。在线文档可能随版本更新；不将其每一条语义自动视为项目锁定版本的实测结果。

## 摘要

Deno 默认限制文件、网络、环境变量及子进程等敏感 I/O；`--allow-*` 可限制到具体资源，`--deny-*` 优先于对应 allow，`-A` 关闭沙箱。同一线程执行的模块共享权限，依赖不会获得独立的模块级安全边界。

初始静态模块图的加载不经过普通 I/O 权限检查；加载后执行的 I/O 仍受限制。文档区分可静态解析的 import 与非字面量动态 import，不能用“没有 allow-net”推导“绝不下载依赖”。

## 关键边界

- `--allow-run` 启动的子进程不继承 Deno 的受限权限集合；允许启动 deno 或 shell 尤其危险。
- FFI / Node-API native code 可直接调用操作系统，不能依赖 JavaScript 权限层约束。
- `Deno.permissions.revoke` 将权限降为 prompt，不是永久 deny；配合 `--no-prompt` 才会在后续缺少授权时直接失败。
- 为部署收窄权限是基于资源清单的设计工作；本文未审计或修改 Searcher 启动参数。
