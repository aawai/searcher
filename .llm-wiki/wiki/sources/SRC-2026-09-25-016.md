# React 19 副作用同步与清理机制官方权威指南

## Summary

本源文档是 React 官方关于 `useEffect` 副作用模型、依赖项追踪与清理函数（Cleanup Function）的深度指南。React 的 Effect 旨在让组件能够与 React 范围之外的系统（如浏览器 API、外部网络请求、DOM 测量观察器等）保持同步。

文档系统性地梳理了编写 Effect 的三步法：
1. **声明 Effect**：在组件渲染完成后执行副作用代码；
2. **指定依赖项数组**：仅在依赖的响应式值发生实质变化时重新触发；
3. **添加清理函数**：在组件卸载或下一次 Effect 执行之前停止或反转上一轮副作用（如取消订阅、移除事件监听、断开 Observer 连接、中断正在进行的 AbortController 网络请求）。

在 [[entities/searcher-项目]] 的前端架构中，`ResizeObserver` 的生命周期管理（`web/src/components/searcher/WebAppLauncher.tsx` 中的 `useDesktopColumns`）严格遵循这一铁律：在 `useEffect` 中挂载 `ResizeObserver`，并在返回的清理闭包中执行 `observer.disconnect()`；便签协同与状态轮询模块也通过返回清理函数安全断开 SSE 连接与全局键盘事件监听，确保了在单页路由频繁切换、面板启闭过程中系统绝对零内存泄漏与零悬挂监听。

## Key Takeaways

1. **每一个 Setup 都有对应的 Cleanup**：无论连接外部服务还是挂载原生 API 观察器，必须在清理函数中对等反转（Observe 对应 Disconnect，Subscribe 对应 Unsubscribe）。
2. **清理消除异步竞争态与内存泄漏**：在网络或实时流场景下，利用 AbortController 或布尔标识位在清理阶段废弃过期响应，杜绝竞态覆盖。
3. **隔离渲染逻辑与外部副作用**：纯数学计算与可由 props/state 推导出的逻辑应在组件主体中同步完成，严禁滥用 Effect 充当数据转换流水线。
