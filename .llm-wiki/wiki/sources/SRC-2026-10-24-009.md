# Same-Document View Transitions for Single-Page Applications
> _Original: [https://developer.chrome.com/docs/web-platform/view-transitions/same-document](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)_

## Summary

Chrome for Developers 的 same-document View Transition 指南。`document.startViewTransition(update)` 先截取旧状态快照，再执行回调更新 DOM，随后捕获新状态并构建 `::view-transition` 伪元素树（`group` → `image-pair` → `old`/`new`）。`old` 是静态截图，`new` 是实时渲染；默认动画为 cross-fade，全部由 CSS 动画驱动，可用 CSS 或 WAAPI（`pseudoElement` 选项）定制。

共享元素过渡依赖 `view-transition-name`：名称在单个快照中必须唯一，否则过渡被跳过。前后两个状态中的元素**不必是同一 DOM 节点**——点击时给缩略图临时设置名称，在回调内移除并让目标元素持有同名，即可让缩略图"变成"大图。只在单侧存在的名称会产生只有 `old` 或只有 `new` 的 image-pair，可用 `:only-child` 定义进入/退出动画。

## Key Takeaways

- 回调返回 Promise 期间页面被冻结：网络请求应在调用 `startViewTransition` 之前完成，等待字体/图片必须加激进超时（示例 100ms）。
- 过渡是增强而非依赖：不要 `await transition.ready` 后让业务流程失败；用 `updateCallbackDone` 表示 DOM 更新完成，`finished` 表示视觉稳定。重复名称导致的跳过不应让切换报错。
- `prefers-reduced-motion` 不等于"无动效"，可改用更克制的动画（Searcher 采用同时长纯透明度）。
- 支持检测：`typeof document.startViewTransition === "function"`，不支持时直接更新 DOM。
- Searcher 的 `web/src/lib/shared-element.ts` 将 `startViewTransition`/`waitForElement`/`uniqueId` 注入为环境依赖，不支持时返回 `"instant"`；首页 AI 回答卡片"展开"到 `/ask/:id` 使用该机制，名称按快照唯一交接。
