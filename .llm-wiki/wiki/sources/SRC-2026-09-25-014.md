# MDN ResizeObserver 规范与响应式容器感知架构文档

## Summary

本源文档是 MDN 关于 Web API 中 `ResizeObserver` 接口的官方参考规范。`ResizeObserver` 提供了一种高性能、轻量且无布局抖动（layout thrashing）的方式来监听 DOM 元素的内容区域（`contentRect`）或盒子尺寸（`contentBoxSize` / `borderBoxSize`）的变化，并在元素尺寸变动时触发异步回调。

与传统的 `window.onresize` 监听视口变化不同，`ResizeObserver` 专注于**容器级**的尺寸感知。文档详细介绍了其生命周期方法：`observe()` 绑定目标节点、`unobserve()` 移除单个监听、以及 `disconnect()` 清除全部监听。在现代组件化前端开发中，尤其是在面板可折叠（40%/65%/90%）、抽屉缩放或多栏布局下，视口宽度不能代表组件容器的可用宽度。在 [[entities/searcher-项目]] 的前端架构中，桌面网格通过 `useDesktopColumns` 钩子封装了 `ResizeObserver`，监听宿主 `.launcher-grid` 的内容宽度，以 `(width + col_gap) / (col_w + col_gap)` 纯数学推导当前网格的最大列数（至少 2 列），实现了组件级完全自适应且无多余重绘的响应式桌面排版。

## Key Takeaways

1. **容器优先而非视口优先**：响应式网格列数的推导以实际渲染容器宽度为单一事实来源，避免视口断点与局部抽屉宽度不匹配产生的列数撕裂。
2. **读写分离规避回流**：通过观察者回调获取几何尺寸，利用 CSS 自定义属性与计算样式读取 `col_w` 和 `gap`，只在计算结果真正变更时触发 React 状态更新。
3. **及时清理生命周期**：在 React 的 `useEffect` 卸载清理阶段必须调用 `observer.disconnect()`，防止由于组件切换或路由跳转引起的内存泄漏与悬挂引用。
