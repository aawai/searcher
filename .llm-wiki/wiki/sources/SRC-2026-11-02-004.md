# fflate README

原文：[GitHub 101arrowz/fflate](https://github.com/101arrowz/fflate/blob/master/README.md)；证据：[提取文本](../../raw/sources/SRC-2026-11-02-004/extracted.md) 第 174–730 行（前 173 行为 GitHub 导航，未使用）。

## 摘要

fflate 是纯 JS 的 DEFLATE/GZIP/Zlib/ZIP 库，主打体积小与速度（第 178–200、712–722 行）。ZIP 相关 API 分三类：一次性的 `zip`/`unzip`（含同步 `unzipSync` 与基于 Worker 的异步版本）、流式 `Zip`/`Unzip`、以及异步流。

与安全相关的几处：

- `unzipSync` 可传 `filter(file)`，在**解压前**按 `file.name`、`file.originalSize` 跳过文件，示例用 10 MB 上限（第 479–490 行）。
- 流式 `Unzip` 对每个文件触发回调，回调里 `file.name` 是字符串、`file` 是流；**只有调用 `file.start()` 之后才会触发 `ondata`**；若 ZIP 没有编码大小，`file.size` 可能为 `undefined`，需自行检查（第 538–557 行）。
- 使用 DEFLATE 压缩的 ZIP 必须先 `unzipper.register(fflate.UnzipInflate)`；未注册压缩方法时 `start()` 会抛错（第 529–533、555 行）。
- 流式喂数据建议每块不超过约 5000 个文件；文件很小（多在 100 字节以下）时块上限 64 kB，以避免栈溢出（第 560–565 行）。
- 同步流中，错误会从 `push()` 抛出（第 365 行注释）。
- 解压结果是**扁平的路径键对象**，目录不嵌套，键就是 ZIP 内的完整路径（第 479–481 行）。

README **没有**讨论路径穿越校验：库只返回名称与字节，落盘路径是否安全由调用方负责（本条是对文档缺失内容的说明，不是库行为的断言）。

## 关键要点

- 想限制解压体积，用 `filter` + `originalSize`，或流式在 `ondata` 内累计；`originalSize` 可能缺失，不能只依赖它。
- 解压键为完整路径字符串，调用方必须校验后再使用。
- 流式路径要手动 `register` 与 `start`，且要确认所有文件都收尾。
