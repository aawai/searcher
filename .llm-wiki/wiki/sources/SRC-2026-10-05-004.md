# The Web Animation Performance Tier List
> _Original: [https://motion.dev/magazine/web-animation-performance-tier-list](https://motion.dev/magazine/web-animation-performance-tier-list)_

## Summary

本文由 Motion（前 Framer Motion）作者 Matt Perry 撰写，系统阐述了现代浏览器渲染管线（Style -> Layout -> Paint -> Composite）与动画性能分级（Tier List）。文章深入分析了主线程（Main Thread）与合成器线程（Compositor Thread）的执行差异，指出引起 Layout 或 Paint 的动画（如 `width`、`height`、`color`、未注册 CSS 变量）会不可逆地阻塞主线程并引发严重掉帧。

作者将 Web 动画技术划分为六大层级：
- **S-Tier（Composite-only）**：通过 CSS、WAAPI 或支持 WAAPI 的库直接在合成器线程驱动 `transform`、`opacity`、`filter` 与 `clip-path`，完全免疫主线程 JavaScript 长任务阻塞，即使 CPU 繁忙仍保持 60/120fps；
- **A/B-Tier**：在主线程计算几何与 DOM 测量，但随后交由合成器线程执行回放（如 FLIP 布局动画）；
- **C/D-Tier**：触发重绘（Paint）或重排（Layout），引发高昂性能代价；
- **F-Tier**：每帧触发主线程强制同步布局（Forced Synchronous Layout）。

## Key Takeaways

- 只有 `transform`、`opacity`、`filter`、`clip-path` 才能在现代浏览器中进入纯合成器线程硬件加速。
- rAF-based 动效库（如旧版 GSAP、手工 JS 循环）始终受限于主线程，一旦主线程存在密集脚本就会产生 jank；而基于 WAAPI / CSS 的 S-Tier 动效直接在 GPU 进程回放。
- 在构建高性能 Web 界面（如壁纸动效、窗口平移、缩放）时，必须将动态属性严格收敛至 S-Tier 属性，避免 CSS 变量未加 `@property` 注册导致的全局样式重算。
