# SQLite Write-Ahead Logging (WAL) 机制与并发架构文档

## Summary

本源文档是 SQLite 官方关于预写日志模式（Write-Ahead Logging,
WAL）的权威技术说明。SQLite 传统上使用 Rollback Journal
保证原子提交与故障回滚，自 3.7.0 起引入了 WAL
模式作为高吞吐嵌入式存储的首选日志机制。

WAL 模式从根本上改变了读写互斥模型：所有新写入追加至独立的 `-wal`
文件中，并通过共享内存 `-shm` 进行索引；读取者在事务开启时记录 WAL
尾部标记，由此读取操作与并发写入操作完全互不阻塞（Readers do not block writers,
and writer does not block readers）。文档系统讨论了 WAL
的检查点机制（`PRAGMA wal_checkpoint`）、单机跨进程共享内存限制以及并发性能收益。在
[[entities/searcher-项目]] 中，底层存储引擎由 [[entities/drizzle-sqlite-store]]
托管，运行于 WAL 模式下，并通过上层 [[concepts/database-queue-serialization]]
规避多写冲突与死锁风险。

## Key Takeaways

1. **读写完全并发**：WAL
   模式消除了数据库读锁对写锁的互斥，大幅度降低由于长时间读取导致的
   `SQLITE_BUSY`。
2. **顺序 I/O 与极少 fsync()**：写入以顺序追加（Sequential
   Append）方式落盘，提升磁盘写吞吐并减轻 I/O 抖动。
3. **配合应用层串行队列**：虽然 WAL 支持读写并发，但 SQLite
   单库同一时间仍仅允许单个写事务。Searcher 采用单写 FIFO
   队列驱动写事务，确保所有修改零冲突原子生效。
