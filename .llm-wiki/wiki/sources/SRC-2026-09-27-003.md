# Deno HTTP Server: Server-Sent Events with WHATWG ReadableStream
> _Original: [https://docs.deno.com/examples/http_server_sse/](https://docs.deno.com/examples/http_server_sse/)_

## Summary

Deno 官方示例详细阐述了如何在 `Deno.serve` 架构中依托 WHATWG 标准 Web Streams API 构建高可靠的 Server-Sent Events（SSE）长连接推送通道。与传统 Node.js 专有 Stream 模块不同，Deno 原生将浏览器与跨运行时统一的 `ReadableStream` 作为标准 HTTP 响应体（`Response(body)`），并规范了客户端断连（Client Disconnect）清理机制与 HTTP 标头协商机制。

在 SSE 架构中，服务端输出为符合规范的文本流格式（行开头为 `data: <payload>\n\n`）。通过在 `new ReadableStream({ start, cancel })` 的 `cancel()` 生命周期回调中注销定时器或事件总线监听器，Deno 能在浏览器页面关闭或主动断开时精确回收资源，有效避免长连接内存泄漏；同时，必须为响应设置 `content-type: text/event-stream` 与 `cache-control: no-store`，禁止代理层缓存和缓冲以保证事件准实时到达下游。

## Key Takeaways

- **Web 标准 ReadableStream 原生流式输出**：Deno HTTP 服务底层使用 WHATWG `ReadableStream` 构造响应体，通过 `controller.enqueue(new TextEncoder().encode(...))` 推送 UTF-8 编码的 SSE 协议帧。
- **精确的反向断连感知（Cancel Callback）**：利用 `ReadableStream` 的 `cancel()` 钩子，当客户端主动关闭连接或网络中断时立即中止上游数据产生与监听注册，彻底杜绝僵尸连接。
- **协议标头规范与缓冲规避**：严格声明 `Content-Type: text/event-stream` 和 `Cache-Control: no-store`，关闭代理服务器（如 Nginx、CDN）的 response buffering，确保事件实时顺畅推送。
- **原生自动重连机制**：浏览器端使用标准 `EventSource` 消费该流，网络抖动或临时中断时浏览器内置握手与自动重连逻辑，大幅简化前端状态维护。
