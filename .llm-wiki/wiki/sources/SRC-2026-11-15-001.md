# How To Corrupt An SQLite Database File
> _Original: [https://sqlite.org/howtocorrupt.html](https://sqlite.org/howtocorrupt.html)_

## 摘要

SQLite 官方列举数据库损坏的来源，包括事务期间直接复制、恢复日志丢失或错配、锁失效及底层存储故障。在线备份可使用 Backup API、`VACUUM INTO` 或 sqlite3_rsync；主文件与恢复所需的 journal/WAL 不能随意拆分。

Unix POSIX advisory lock 下，同一进程绕过 SQLite 直接关闭数据库文件描述符可能解除该进程对文件的锁；SQLite 3.51.0 起部分 WAL 多进程防御不能消除全部风险。通用风险不等于 Searcher 已发生损坏。

本次捕获与 [既有 SQLite 来源](/sources/SRC-2026-10-29-003.md)为同一文档，并非独立佐证。参见 [备份与恢复边界](/concepts/sqlite-backup-and-recovery-boundaries.md)和 [SQLite Store](/entities/drizzle-sqlite-store.md)。
