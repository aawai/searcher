# Function calling (OpenAI API guide)

原文：[OpenAI Function calling](https://platform.openai.com/docs/guides/function-calling)；[提取文本](../../raw/sources/SRC-2026-11-08-005/extracted.md)，共 2177 行。示例以 **Responses API** 为主；Searcher 使用 Chat Completions，事件形态不同，下文已注明。

## 摘要

**调用流程（第 18–75 行）**：五步。带上 tools 发请求；收到 tool call；应用侧执行；把 tool output 连同 call id 发回；得到最终回答或更多 tool call（第 65–71 行）。Tool output 必须引用对应的 call id（第 44 行）。

**定义函数（第 527–557 行）**

- 名称和参数描述要清楚。用 enum 与对象结构排除非法状态。模型已知的参数不要让模型填（第 529–542 行）。
- 初始可用函数宜少于 20 个（软建议，第 546 行）。
- 函数定义注入 system message，计入上下文并按输入 token 计费（第 555 行）。

**处理调用（第 559–860 行）**

- 一次响应可能有 0、1 或多个调用，应按多个处理（第 561 行）。
- `arguments` 是 JSON 编码字符串（第 563 行）。
- 结果通常为字符串，格式自定；无返回值的函数也应返回表示成败的字符串（第 846–852 行）。

**配置（第 995–1094 行）**

- `tool_choice`：`auto` / `required` / 指定函数 / `allowed_tools` / `none`（第 999–1026 行）。
- `parallel_tool_calls: false` 保证一轮内调用 0 或 1 个工具（第 1036 行）。
- **Strict mode**：建议始终开启。要求每个 object 都设 `additionalProperties: false`，且所有字段都列入 `required`；可选字段用 `null` 类型表示（第 1044–1051 行）。**Chat Completions 默认非 strict**；Responses 会尝试自动规范化（第 1053–1061 行）。

**流式（第 1137–1562 行）**：参数通过增量事件到达，客户端按输出索引（Responses 为 `output_index`）累积 `delta`，最后得到完整调用。Chat Completions 对应的是 `choices[0].delta.tool_calls[i].index`，这一点是读 Searcher 代码得出的对应关系，不是本来源的原文。
