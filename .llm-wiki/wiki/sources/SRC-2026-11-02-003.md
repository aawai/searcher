# File Upload Cheat Sheet (OWASP)

原文：[OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)；证据：[提取文本](../../raw/sources/SRC-2026-11-02-003/extracted.md) 第 221–382 行。第 325 行因长度被截断，以下未引用其全文。

## 摘要

该清单强调**纵深防御，没有单一手段足够**（第 267 行）。顶层原则（第 229–241 行）：只列允许的扩展名并先做输入校验；按内容校验类型，不信任可伪造的 `Content-Type`；由应用生成文件名；限制文件名长度与字符、限制大小；只允许授权用户上传；存放到另一台服务器，否则放在 webroot 之外，公开访问时用 handler 把 id 映射到文件名；有条件时做杀毒/沙箱与 CDR；保持库更新；上传接口要防 CSRF。

威胁分两类（第 247–263 行）：恶意文件（利用解析器漏洞如 ImageTrick/XXE、ZIP bomb/XML bomb 耗尽存储、覆盖已有文件、客户端活动内容）与公开检索带来的附加风险（泄露其他文件、小请求大响应的 DoS、托管非法内容）。

具体控制中与本项目相关的部分：

- **扩展名**：需在解码后校验，注意双扩展名、空字节、大小写、NTFS 备用数据流（含 `:` 的文件名应拒绝）；黑名单本身是弱防护（第 269–296 行）。
- **Content-Type 与签名**：Content-Type 由用户提供、易伪造，只能作快速检查；文件签名校验“绕过常见且容易”，不应单独使用（第 298–310 行）。
- **文件名**：推荐 UUID 等随机文件名；若需保留用户文件名，限制长度、限制字符集、限制前导点与连续点（第 312–323 行）。
- **内容**：图片应解码后重新编码为允许格式并去除元数据；重写不保证清除全部恶意内容，且图像处理器本身处理不受信输入，需使用最新版本并设置受限格式、资源限制与沙箱；**不推荐 ZIP 文件**（第 333–335 行）。
- **存储与权限**：优先异机，其次 webroot 之外；数据库存文件可行但有性能与 SQLi 面（第 343–352 行）；最小权限（第 367–375 行）。
- **限制**：若会解压或处理文件，大小限制要在**解压后**计算，并用安全方法计算 ZIP 大小；下载侧也要限流（第 377–381 行）。

## 关键要点

- Content-Type 与扩展名都不是证据，内容检查才是；但签名检查单独也不够。
- 随机服务端文件名同时消除路径遍历、覆盖与 NTFS 别名类问题。
- 图片处理库是攻击面：限像素、限格式、保持更新。
- 解压后大小才是真实资源消耗上限。
