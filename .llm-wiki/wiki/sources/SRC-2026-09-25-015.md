# React 19 状态保留与重置机制官方权威指南

## Summary

本源文档是 React 官方教程中关于组件状态在渲染树（UI Tree）中的生命周期、状态保留（Preserving State）与状态重置（Resetting State）的权威指导。React 组件的状态并非保存在 JSX 元素内部，而是由 React 运行时绑定在组件于 UI 树中所处的具名位置上。

文档深入阐明了两条铁律：
1. **相同位置相同组件保留状态**：如果在两次渲染之间，同一个组件类型渲染在 UI 树的完全相同结构位置上，React 将自动保留其内部所有 `useState` 与 `useReducer` 状态，即使传入的 props 发生变化。
2. **位置变动或组件类型变更彻底重置状态**：当树结构发生改变（如被不同的标签包裹或在条件分支中处于不同槽位），或者使用不同的 `key` 时，React 将彻底卸载旧子树并销毁所有挂载状态。

在 [[entities/searcher-项目]] 的前端架构中，这一心智模型被严格贯彻于桌面启动器网格：网格项目（`SortableTile`）通过稳定的 canonical ID 作为 `key`，在搜索过滤、大小文件夹动态切换和多尺寸拖拽重排时，保证了非受控拖拽手柄、折叠面板以及上下文菜单的局部状态不发生非预期重置与闪烁。

## Key Takeaways

1. **状态与 UI 树位置绑定**：组件状态的宿主是 React 运行时的虚拟节点位置，通过保持渲染层级结构的一致性，能够稳定维护组件运行状态。
2. **使用稳定的 Key 明确身份**：在列表与网格渲染中，禁止使用随机数或数组索引作为 `key`；必须使用领域唯一实体 ID（如 `app.id` 或 `folder.id`）作为 key，防止列表重排时出现状态错位串联。
3. **显式控制重置**：当需要重置表单或交互状态时，通过切换 key 或条件渲染不同分支显式触发子树重置，避免在 effect 中进行复杂的级联重置操作。
