# ExternalStoreRuntime
> _Original: [https://www.assistant-ui.com/docs/runtimes/custom/external-store.md](https://www.assistant-ui.com/docs/runtimes/custom/external-store.md)_

## Summary

`ExternalStoreRuntime`（通过 `useExternalStoreRuntime` Hook 使用）是 `@assistant-ui/react` 面向“应用自管对话状态”场景的运行时适配器，适用于状态已由 Redux、Zustand、TanStack Query 或自定义后端同步层管理的 React 应用。宿主通过传入 `messages`（或带分支结构的 `messageRepository`）、`isRunning` 与回调处理器，由 Runtime 按“能力矩阵”动态开启对应的 UI 功能。

文档系统阐述了两条核心集成机制：一是消息格式转换（内联 `convertMessage` 或带 `joinStrategy` 与 `getMetadataKey` 缓存优化的 `useExternalMessageConverter`）；二是分支与生命周期管理——线性 `messages` 数组假设消息按顺序串联，而分支对话需要通过 `ExportedMessageRepository.fromBranchableArray()` 构造树状仓库并配合 `setMessages`（以及实验性的 `unstable_onBranchChange`）同步选中分支的 `headId`。

此外，文档覆盖了能力矩阵（`onNew`、`setMessages`、`onEdit`、`onReload`、`onCancel`、`onAddToolResult`、`onLoadEarlier`、`queue` 等）、通过 `thread.export()` / `thread.import()` 进行完整分支树快照往返、基于 `createMessageQueue` 的双通道（`steerItems` / `items`）消息排队，以及依赖服务端检查点的 `canResume` + `onResume` 断流续传契约。

## Key Takeaways

- **能力由处理器存在与否驱动**：传入 `onNew` 开启发送、`setMessages` 开启分支切换、`onEdit` 开启编辑、`onReload` 开启重新生成、`onCancel` 开启生成中断，缺省处理器对应 UI 能力自动关闭。
- **树状分支依赖 `ExportedMessageRepository`**：使用 `ExportedMessageRepository.fromBranchableArray(items, { headId })` 时，每条消息必须具备唯一 `id` 与 `parentId`（共享 `parentId` 即形成兄弟分支），且父节点在数组中须位于子节点之前。
- **不可变更新与陈旧闭包防护**：异步回调（如流式追加或 `onLoadEarlier`）必须基于 Store 最新状态构造新数组，避免覆盖并发到达的更新或使用直接数组 push。
- **快照导出/导入与历史分页**：`thread.export()` 返回可序列化的 `ExportedMessageRepository` 快照；在外部 Store 上调用 `thread.import()` 时必须实现 `onImport`，否则会主动拒绝导入以防状态漂移。
