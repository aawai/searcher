## 新概念页与代码对照

新增 4 个概念页，内容来自读码和本地函数调用，均不是安全审计；本轮未修改项目代码。

- [SSRF and Outbound Fetch Boundaries](../wiki/concepts/ssrf-and-outbound-fetch-boundaries.md)：经 `deno eval` 验证，`[::1]`、`[::ffff:7f00:1]` 带方括号的 hostname 不会被 `isPrivateOrRestrictedIp` 识别。默认配置下它们仍被拒绝，但原因是 DNS 查询无结果；`allowDnsLookup: false` 时会被放行，该参数目前只在测试中使用。十六进制形式的 IPv4-mapped 地址和 NAT64 前缀也未被识别。DNS rebinding 未消除，代码注释已说明。Provider Base URL 不做 DNS 检查。
- [Field Encryption and Key Management](../wiki/concepts/field-encryption-and-key-management.md)：AES-256-GCM 与 96 位随机 IV 符合来源要求。与 OWASP 的差异有两处：生产启动流程没有注入密钥，实际从环境变量读取（`CryptoVault`/`AiService` 本身支持注入）；没有 key ID，也没有轮换路径。
- [SearXNG Web Search Integration](../wiki/concepts/searxng-web-search-integration.md)：`new URL("/search", base)` 会丢弃 `SEARXNG_URL` 的子路径，已由 `deno eval` 验证。JSON 输出未启用时返回的 403 只显示通用错误。
- [Data Router Lifecycle in Searcher](../wiki/concepts/data-router-lifecycle.md)：`App.tsx` 用 `useState` 持有 router，与官方约束不一致。已确认两点事实：该组件在 StrictMode 下渲染；`createBrowserRouter` 在创建时就订阅 history。开发模式下会遗留一个未 dispose 的 router，这一点属于推断，未经运行观察。
