## 实质发现

1. Cache API 不遵循 HTTP 缓存头，条目不会自动过期；Cache-Control: no-store 不能替代 Worker 对敏感响应的显式排除与既存条目清理。[OWASP 摘录](../raw/sources/SRC-2026-10-24-004/extracted.md)，363–370 行。
2. network-first 仍可写入并返回历史缓存，不能与 network-only 混同；Manifest scope、Worker scope 和账号授权是独立边界。[MDN 缓存摘录](../raw/sources/SRC-2026-10-24-002/extracted.md)、[Manifest 摘录](../raw/sources/SRC-2026-10-24-005/extracted.md)。
3. 来源存在一处真实冲突：OWASP 建议 sw.<hash>.js，而 web.dev 建议稳定 Worker URL，并说明旧缓存 HTML 可能导致新注册 URL 永远不可达。已在来源页和生命周期概念页保留双方依据。Wiki 采用稳定 Worker URL、版本化资源缓存的设计选择；这是基于更新机制的推导，不是声称两份资料一致，也不是对 Searcher 当前实现的验证。[web.dev 摘录](../raw/sources/SRC-2026-10-24-003/extracted.md)，371–381 行。
