# OWASP Cross-Site Request Forgery Prevention Cheat Sheet

原文：[OWASP Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。证据：[不可变提取文本](../../raw/sources/SRC-2026-10-26-003/extracted.md)，正文第 293–340、515–570、628–670 行。

## 摘要

Cookie 认证依赖浏览器自动携带凭证，必须为状态变更请求建立 CSRF 防护。优先复用框架能力；文档介绍 synchronizer token、signed double-submit cookie，以及满足相应前提的 Fetch Metadata、自定义 header 与严格 CORS 策略。

`SameSite` 是纵深防御，不应无条件视作完整防护。same-site 不等于 same-origin：兄弟子域可能仍属于同站；`Lax` 允许跨站顶层安全方法导航，因此 GET 不得承担状态变更。

## 关键边界

- Token 应绑定会话、不可预测，不放 URL 或日志；synchronizer pattern 不以 Cookie 传送 token。
- 自定义 header 方案依赖浏览器 preflight 与精确受控的 CORS allowlist；宽泛信任子域可能让防护失效。
- XSS 可绕过 CSRF 防护；客户端若从攻击者控制的 URL 等输入构造请求，也可形成 client-side CSRF。
- `HttpOnly` 阻止脚本读取 Cookie，不阻止浏览器发送认证请求；本文不是 Searcher 已通过 CSRF 审计的证明。

## 与既有知识的修正

[Session Security and Isolation](/concepts/session-security-and-isolation.md) 原有 Cookie 概述将多个属性合并描述为防范 XSS 与 CSRF；必须区分凭证读取限制、传输保护、跨站携带限制和服务端请求来源校验，详见 [CSRF Defense Boundaries](/concepts/csrf-defense-boundaries.md)。
