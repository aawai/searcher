# Assistant Context API
> _Original: [https://www.assistant-ui.com/docs/guides/context-api.md](https://www.assistant-ui.com/docs/guides/context-api.md)_

## Summary

Assistant Context API 是 `@assistant-ui/react` 向自定义 React 组件暴露运行时状态、命令操作与生命周期事件的作用域感知上下文体系，所有内置 Primitives（`ThreadPrimitive`、`MessagePrimitive`、`ComposerPrimitive` 等）均构建于其上，底层由 `<AssistantRuntimeProvider>` 提供的 Runtime 实例驱动。

状态按组件挂载位置分层解析为作用域（Scopes）：从顶层 `threads`（ThreadList）到 `threadListItem`、`thread`，再到 `message`、`part`、`chainOfThought`、`attachment` 与 `composer`（主输入与编辑模式各自拥有独立 composer 作用域），以及 `suggestions`、`tools` 与 `modelContext`。子作用域组件可以直接读取父作用域数据（如消息内组件读取 `s.thread.isRunning`）。

API 围绕三个核心 Hook 分离关注点：`useAuiState(selector)` 类似 Zustand selector 订阅细粒度不可变状态切片；`useAui()` 返回不触发订阅的命令客户端用于事件处理器或按需 `getState()`；`useAuiEvent(event, handler)` 订阅如 `composer.send`、`composer.attachmentAddError`、`message.branchSwitched` 等过渡事件以触发副作用。

## Key Takeaways

- **Selector 引用稳定性要求**：`useAuiState` 选择器绝不能每次返回新对象或新数组字面量，否则会触发无限重渲染；昂贵派生计算应在拿到稳定切片后配合 `useMemo`。
- **作用域解析与 `optional` 视图**：作用域随渲染位置动态绑定；处于不确定的嵌套层级时，可通过 `s.optional.message?.role` 读取而不抛出作用域缺失错误。
- **防止陈旧作用域引用**：结构变化（如切换线程）会产生新的 `aui` 客户端实例，不应把 `aui.thread` 缓存在 closure 或 effect 依赖中，而应在调用时从 `aui` 现取。
- **事件与状态的边界**：UI 渲染用 `useAuiState`，副作用响应（如错误提示、`composer.attachmentAddError`）用 `useAuiEvent`，主动操作用 `useAui()`。
