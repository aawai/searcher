# SQLite checkpoint API

原文：[SQLite sqlite3_wal_checkpoint_v2](https://www.sqlite.org/c3ref/wal_checkpoint_v2.html)；[提取文本](../../raw/sources/SRC-2026-11-05-003/extracted.md)，第 28–54 行。

## 摘要

`PASSIVE` 不等待读写者，也不调用 busy handler，因此可能未完成；`FULL` 等待写入者及旧快照读取者，期间阻塞新写入；`RESTART` 进一步等待所有读取者不再使用 WAL，以便下一写入者从头开始；`TRUNCATE` 成功前还会将 WAL 截断至零字节。`NOOP` 不回写帧，仅用于读取输出计数。

所有模式需取得 checkpoint 锁，锁冲突立即返回 `SQLITE_BUSY` 而不调用 busy handler。FULL、RESTART、TRUNCATE 在等待写锁或读取者时还可能调用 busy handler；若其拒绝继续等待，则尽可能执行非阻塞 checkpoint 并返回 `SQLITE_BUSY`。输出帧计数有非 WAL、错误及处理所有附加数据库的特殊规则，不能单凭返回或文件大小推断备份一致性。`PRAGMA wal_checkpoint` 可从 SQL 调用该接口。
