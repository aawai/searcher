# Best Practices for Persisting Application State with IndexedDB

> _Original:
> [https://web.dev/articles/indexeddb-best-practices-app-state](https://web.dev/articles/indexeddb-best-practices-app-state)_

## Summary

Chrome 团队工程师 Philip Walton 在本文中系统阐述了利用浏览器内置 IndexedDB
进行应用状态持久化与离线优先（Offline-First）架构的最佳工程实践。将客户端状态保存在
IndexedDB 中可以极大缩短二次访问的初屏渲染时间，并通过
Stale-While-Revalidate（SWR）策略实现静默增量刷新。

然而，客户端存储环境存在高不确定性：无痕浏览限制、磁盘配额耗尽、用户主动清除存储以及老旧版本残留数据都可能导致写入失败或读取异常。因此，架构上必须遵循“双层模型”——始终保留内存中的运行时单一可信源（In-Memory
Source of
Truth），并将持久化作为异步镜像；同时避免将整个庞大的单体状态树作为单个大对象写入，以防止
Structured Clone 算法在浏览器主线程上产生严重掉帧与 Long Tasks。

## Key Takeaways

- **内存优先与异步镜像策略**：不能将 IndexedDB 作为唯一的实时 UI
  依赖，必须维持内存状态副本以防无痕模式或存储受限时界面崩溃。
- **避免单体大对象写入**：IndexedDB
  写入对象时在主线程执行结构化克隆算法（Structured
  Clone），超大对象会造成主线程阻塞与卡顿，应当按业务实体将状态拆分为细粒度独立记录。
- **严格的版本升级与防御性迁移**：利用 `onupgradeneeded` 编写容错的 Schema
  升级逻辑，充分防御旧版本可能遗留的脏数据或残缺字段。
