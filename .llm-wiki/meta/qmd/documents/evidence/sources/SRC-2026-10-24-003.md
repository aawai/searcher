# web.dev：The Service Worker Lifecycle

原文：https://web.dev/articles/service-worker-lifecycle

作者：Jake Archibald。摘录中的文章更新时间：2016-09-29；本轮新增到 Wiki，不代表近期发布。

## 摘要

生命周期让新版 Worker 在不打断旧版的情况下准备资源，并尽量保持客户端版本一致。安装成功的新版通常进入 waiting，直到旧版没有受控客户端；普通刷新期间新旧文档可能重叠，因此刷新不保证激活新版。

`skipWaiting()` 可主动越过等待，但会让旧页面的后续请求转由新版处理。`clients.claim()` 会接管未受控客户端。两者都可能破坏默认的一致性边界，不应不加判断地作为样板调用。更新可通过 installing/waiting/active、updatefound、statechange 与 controllerchange 观察。

## 关键约束

- 新版下载、解析或安装失败时，旧版仍可继续 active。
- 使用版本化缓存准备新版，避免覆盖正在被旧 Worker 使用的内容。
- Cache Storage 是 origin 级共享存储，清理必须限制在本应用命名前缀内。
- Worker 脚本保持稳定 URL，避免旧缓存 HTML 永远指向旧脚本 URL。
- 用户触发 postMessage 后再 skipWaiting 是文中给出的更新交互方案之一，不是本轮已验证的项目实现。
