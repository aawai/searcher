# Taming 'Large Chunks' in Vite + React: Why It Happens and How I Shrunk My Main Bundle
> _Original: [https://mykolaaleksandrov.dev/posts/2025/11/taming-large-chunks-vite-react/](https://mykolaaleksandrov.dev/posts/2025/11/taming-large-chunks-vite-react/)_

## Summary

本文深入分析了 Vite 生产构建时常见的“Some chunks are larger than 500 kB after minification”告警根因与系统化治理方案。在默认配置下，Vite 会将应用代码及所有静态顶层 import 的 `node_modules` 依赖全量打包至单一 `index.js`，造成首屏下载缓慢、低端设备主线程解包解析阻塞以及 Core Web Vitals (FCP/LCP/INP) 恶化。

作者提出了结合 `manualChunks` 与 `React.lazy()` + `<Suspense>` 的两阶段优化架构：
1. **Vendor 分块**：将极其稳定且体积庞大的第三方运行时（React 核心、大型图表/编辑器、图标库）提取为独立 chunk，利用不可变哈希实现跨版本长效缓存；
2. **路由懒加载**：将各非首页页面改为动态 import，仅保留首页关键路径。

## Key Takeaways

- 顶层静态 import 会将异步页面的依赖提前拖入主入口闭包，使优化无法生效。
- 不要通过机械调大 `chunkSizeWarningLimit` 来掩盖包体积问题，首屏 JS 预算必须设定硬性门禁。
- 动态路由切分结合 Suspense 与错误边界，是保证 App Shell 持续可用、防止白屏的关键工程契约。
