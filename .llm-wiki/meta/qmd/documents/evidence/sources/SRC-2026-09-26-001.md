# Base UI: Slider Component Anatomy and Accessibility
> _Original: [https://base-ui.com/react/components/slider](https://base-ui.com/react/components/slider)_

## Summary

Base UI's Slider component (`@base-ui/react/slider`) provides an unstyled, accessible React primitive for selecting scalar values or multi-value ranges along a track. The component architecture decomposes the slider into specialized parts: `Slider.Root` for overall state and constraints, `Slider.Control` for hit-testing and dragging, `Slider.Track` and `Slider.Indicator` for visual presentation, and `Slider.Thumb` for draggable keyboard and pointer handles.

Crucially for web accessibility, `Slider.Thumb` renders a visually hidden native `<input type="range">`. In Base UI's implementation, `aria-labelledby` passed to `Slider.Root` is forwarded via `labelId` context to the nested input, but `aria-label` passed to `Slider.Root` only applies to the outer group `<div>`. To satisfy WCAG 2.5.3 / 4.1.2 accessible name requirements on the range input, `aria-label` must be forwarded directly to the individual `Slider.Thumb` elements. Multi-thumb range sliders require an `index` prop on each thumb for SSR synchronization and distinguishing labels for endpoints.

## Key Takeaways

- **Thumb Input Anatomy**: Each `Slider.Thumb` hosts a visually hidden `<input type="range">` that holds the actual accessibility tree state (`aria-valuenow`, `aria-label`, `min`, `max`, `step`).
- **Label Propagation**: Setting `aria-label` solely on `Slider.Root` only labels the container group; the interactive `<input type="range">` remains without an accessible name unless `aria-label` is forwarded directly to `Slider.Thumb` (unlike `aria-labelledby`, which Base UI propagates via context).
- **Scalar vs. Range Value Models**: Single-value sliders accept a numeric `value` or `defaultValue` and require exactly one thumb. Multi-value range sliders accept arrays and require one thumb per entry with distinguishing labels.
- **SSR Index Requirement**: When multiple thumbs exist, providing `index={i}` ensures server and client rendering trees align correctly during hydration.
