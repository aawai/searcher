# Vite - Code Splitting Strategy
> _Original: [https://dev.to/markliu2013/vite-code-splitting-strategy-5a69](https://dev.to/markliu2013/vite-code-splitting-strategy-5a69)_

## Summary

本文详细探讨了基于 Vite 与 Rollup 的前端代码切分（Code Splitting）策略。传统单 chunk 打包模式将所有初始代码与路由组件打包在一起，不仅导致首屏无法按需加载，还因哈希更新频繁而破坏客户端长效缓存。

文章系统剖析了 Vite 默认的代码分割演进（Vite 2.9 前后依赖与业务代码的合并变化），并重点阐述了通过 Rollup `manualChunks` 进行精细化分块的实践。作者分析了对象形式与函数形式的 `manualChunks` 区别，指出函数形式基于模块 ID 进行动态路由判断与第三方包隔离的优越性，避免过度切分带来多重网络请求开销。

## Key Takeaways

- 单一巨石 Bundle 会破坏长效网络缓存，且严重拖累首屏初始化时间与 Core Web Vitals。
- `manualChunks` 对象形式会将第三方包及其所有传递依赖全部拖入同一静态 chunk，而函数形式能依据 module ID 实现精准隔离。
- 代码切分不宜过度碎片化，应当围绕路由边界与大型独立重库（如 Markdown 解析、AI 交互流）进行生命周期解耦。
