# External Store Runtime
> _Original: [https://www.assistant-ui.com/docs/api-reference/external-store/runtime.md](https://www.assistant-ui.com/docs/api-reference/external-store/runtime.md)_

## Summary

本页为 `ExternalStoreAdapter`、`ExternalThread`、`ExternalThreadProps` 与 `useExternalStoreRuntime` 的完整类型参考，精确定义了外部存储适配器的状态字段、操作回调、分支仓库结构与实验性能力边界。

其中关键契约包括：`isDisabled`（彻底禁用输入、附件、发送与编辑）与 `isSendDisabled`（仅阻止新消息发送，保持输入可用且编辑 composer 不受影响）的区分；`isRunning` 显式覆盖默认“末条消息状态”启发式；以及 `messageRepository`（`ExportedMessageRepository`）与 `unstable_messageRepositoryInstance`（由宿主直接持有 `MessageRepository` 实例并在多会话路由时原子切换）的差异。

参考还完整列出了底层 `MessageRepository` 的内部方法与并发/乐观更新语义（如 `evictOffBranchOptimisticMessages`、`exportedHeadId`、`switchToBranch`、`addOrUpdateMessage`、`deleteMessage`），以及 `onDelete` 的待决确认语义、`setMessages` 对取消运行后撤销尾部消息存活的必要性，和 `adapters.attachments` / `speech` / `dictation` / `voice` / `feedback` / `threadList` 接口签名。

## Key Takeaways

- **`setMessages` 控制运行时回写存活**：取消运行或由运行时移除消息时，若未提供 `setMessages`，运行时无法持久化该删除，尾部用户消息会留在线程中；由适配器自行移除消息则须同步回传新列表。
- **`isDisabled` vs `isSendDisabled`**：`isSendDisabled` 仅阻止主线程发送新消息（`composer.canSend === false`），允许继续输入且编辑消息的 composer 故意忽略该标志。
- **乐观消息与分支导出清理**：`MessageRepository.evictOffBranchOptimisticMessages` 仅在离开分支时清理 `metadata.isOptimistic` 节点；`exportedHeadId()` 跳过乐观占位节点以保证持久化分支头有效。
- **客户端工具调用默认关闭**：`unstable_enableToolInvocations` 默认 `false`，避免外部存储运行时已自行调度工具时出现重复执行。
