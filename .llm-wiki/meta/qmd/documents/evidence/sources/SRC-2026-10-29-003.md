# How To Corrupt An SQLite Database File

原文：[SQLite 官方文档](https://www.sqlite.org/howtocorrupt.html)；证据：[捕获的原始 HTML](../../raw/sources/SRC-2026-10-29-003/original/source.html)，第 229–280、316–366 行。

**提取限制：**本来源的 `extracted.md` 仅记录提取失败；下列摘要依据已捕获的原始 HTML 人工整理，而非提取文本。原始包的失败状态保留不变。

## 摘要

在事务进行时直接复制数据库文件可能混入新旧内容；SQLite 文档列出 Online Backup API、`VACUUM INTO` 和 `sqlite3_rsync` 等可用于运行中数据库的复制方式。崩溃后的 hot journal 或 WAL 对恢复有重要作用，错误删除、移动或与数据库错配可能导致无法恢复或损坏。

在使用 POSIX advisory lock 的 Unix 环境中，同一进程绕过 SQLite 直接打开并关闭数据库文件，可能解除该进程持有的相关锁，使其他连接误以为锁仍有效。SQLite 3.51.0 开始为部分 WAL 多进程情形增加防御，但文档强调这并非完整修复；此为一般风险，并非对 Searcher 实现的审计结论。
