# Deno node:sqlite DatabaseSync API and Embedded Persistence Contract

> _Original:
> [https://docs.deno.com/api/node/sqlite/~/DatabaseSync](https://docs.deno.com/api/node/sqlite/~/DatabaseSync)_

## Summary

本文档详细记录了 [[entities/deno-runtime]] 内置提供的 `node:sqlite` 模块及其核心
`DatabaseSync` 类的规范与操作契约。Deno 自 v2.2 起原生内嵌了该同步 SQLite
引擎接口，提供了高效的本地嵌入式关系型存储支持。`DatabaseSync`
允许开发者直接打开持久化本地磁盘数据库文件或 `:memory:` 内存临时数据库，通过
`exec()` 执行无返回值的 DDL 与配置命令，并通过 `prepare()` 预编译 SQL 语句获得
`StatementSync` 句柄，杜绝 SQL 注入隐患。

文档重点阐释了 `DatabaseSync` 的事务管理、连接配置选项（如
`readOnly`、`foreignKeys`、`allowExtension`）及权限鉴权接口（`setAuthorizer`）。在单进程多协程的高并发环境下，`DatabaseSync`
的所有操作均为阻塞性同步执行，这要求上层应用必须构建严格的队列调度与单线程排队访问边界，防止多微任务并发导致底层
SQLite 文件锁争用或数据库死锁。

## Key Takeaways

- **同步执行与队列依赖**：`DatabaseSync` 为同步阻塞调用，在异步应用中必须通过
  [[concepts/database-queue-serialization]]（如 FIFO
  队列调度）隔离事务与异步请求，防止嵌套调用与锁冲突。
- **预编译安全**：所有动态查询与参数写入必须通过 `db.prepare(sql)` 执行，配合
  `.all()` 或 `.run()` 保证类型一致性与防注入。
- **与 Drizzle ORM 的桥接**：[[entities/drizzle-sqlite-store]] 通过适配层挂载于
  `DatabaseSync` 之上，对外暴露类型安全的 Schema 访问与事务闭环。
- **原地全量迁移支持**：结合 SQLite 原生事务，在表结构演进中支持
  [[concepts/sqlite-table-recreation-migration]]，保障数据零丢失。
