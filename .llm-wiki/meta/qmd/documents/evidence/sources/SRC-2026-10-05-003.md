# The Web Animations API vs. CSS
> _Original: [https://blog.logrocket.com/the-web-animations-api-vs-css/](https://blog.logrocket.com/the-web-animations-api-vs-css/)_

## Summary

本文系统比较了 CSS Transitions、CSS Animations 与 JavaScript Web Animations API (WAAPI) 在现代 Web 动效体系中的性能特征与控制能力。WAAPI 结合了 CSS 硬件加速的渲染性能与 JavaScript 的命令式编排灵活性，使开发者能够直接驱动浏览器合成器线程（Compositor Thread）。

文章对比了使用 requestAnimationFrame (rAF) 主线程轮询更新样式的弊端（易受 JS 长任务阻塞引发掉帧与耗电），强调在针对 `transform` 与 `opacity` 等硬件加速属性时，WAAPI 与 CSS Transitions 底层共享同一个浏览器合成引擎，能够实现完全免疫主线程阻塞的 60fps/120fps 平滑回放与精准生命周期控制（pause, reverse, playbackRate, finished promise）。

## Key Takeaways

- WAAPI 直接下沉至 Compositor 线程，当主线程发生重度计算或 GC 时，动效仍可平滑维持流畅度。
- WAAPI 提供了基于 Promise 的结束回调机制与精确的时间轴控制能力，消除了基于类名切换控制 CSS 动效带来的副作用与脆弱性。
- 非合成属性（如 width/height/margin）会强制退化到主线程布局计算，破坏 WAAPI 与 CSS 的性能优势。
