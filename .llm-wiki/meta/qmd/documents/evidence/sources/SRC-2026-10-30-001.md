# OWASP Password Storage Cheat Sheet

原文：[OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)；证据：[不可变提取文本](../../raw/sources/SRC-2026-10-30-001/extracted.md)，第 247–257、293–333、346–360、403–427、429–443 行。前 242 行为站点导航。

## 摘要

口令必须以慢速、带盐的哈希保存，不得明文或可逆加密保存；SHA-256 等快速哈希不适合。首选 Argon2id，最低配置为 m=19456 KiB、t=2、p=1（另列 m=47104/t=1、m=12288/t=3、m=9216/t=4、m=7168/t=5 等价组合）。Argon2id 不可用时用 scrypt（N=2^17、r=8、p=1 等）；仅遗留系统用 bcrypt（工作因子 ≥10，输入上限 72 字节）；需要 FIPS-140 时用 PBKDF2，HMAC-SHA-256 为 600,000 次迭代、HMAC-SHA-512 为 220,000 次、HMAC-SHA-1 为 1,400,000 次且仅限遗留。

盐按用户唯一、通常由库自动生成；pepper 是跨口令共享的秘密，须与数据库分开保存，泄露后更换需强制用户重置口令。工作因子应通过实测选择，单次哈希一般应少于 1 秒；过高会让登录接口成为 CPU 耗尽型 DoS 面。升级工作因子或算法的常用方式是用户下次登录时重新哈希；哈希里应存算法与参数（如 PHC string format），以便混合期共存。

## 关键细节

- PBKDF2 的 HMAC 在口令超过块长（SHA-256 为 64 字节）时先预哈希；部分实现在每次迭代重复预哈希，长口令会放大开销，Django 2013 年出现过相应 DoS。
- 哈希库须接受全部 Unicode 码点及 NUL 字节，哈希前不得降低口令熵。
- 不必隐藏所使用的哈希算法。
