# Hono Validation Guide: Built-in Validator, Third-Party Adapters, and Type Inference

> _Original:
> [https://hono.dev/docs/guides/validation](https://hono.dev/docs/guides/validation)_

## Summary

Hono 的请求校验系统围绕轻量中间件设计展开，提供了原生的 `validator`
基础设施，并与社区主流 Schema 验证库（如 Valibot、Zod）以及 cross-library 的
Standard Schema 规范深度集成。校验目标覆盖 HTTP 请求的各个维度，包括
`json`、`query`、`param`、`header`、`cookie` 以及 `form`。

在 Hono
架构中，校验器兼具门禁防护与强类型注入双重职责：当请求数据通过校验后，可通过
`c.req.valid('<target>')` 获取已被剥离污染、带有完整静态 TypeScript
类型的干净数据。同时，若请求体格式缺失匹配的 `Content-Type` 标头（例如发送 JSON
但未携带
`application/json`），中间件会防御性跳过解析以规避未定义异常，并在单测时提示调用方必须规范携带标头。

## Key Takeaways

- **多目标与分层校验**：支持对路径参数、查询参数、请求体及 Header
  进行原子校验与统一转换（例如将字符串 query 转换为数字）。
- **静态类型安全推导**：经过校验的数据可被 Hono RPC
  客户端端到端推导，为全栈单进程架构提供与 tRPC 媲美的无缝类型契约。
- **自定义 Hook 与错误信封**：可通过校验钩子函数拦截默认的
  `400 Bad Request`，重整为契约规定的统一错误信封格式，防止泄露底层框架异常堆栈。
