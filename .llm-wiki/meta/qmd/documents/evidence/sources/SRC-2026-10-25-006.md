# MDN: line-clamp CSS property
> _Original: [https://developer.mozilla.org/en-US/docs/Web/CSS/line-clamp](https://developer.mozilla.org/en-US/docs/Web/CSS/line-clamp)_

## Summary

`line-clamp` 是 CSS Overflow Module Level 4 中 `max-lines` + `block-ellipsis`（+ 可选 `-webkit-legacy`）的简写：`none | [<integer> || <'block-ellipsis'>]`，`block-ellipsis` 取 `no-ellipsis`、`auto`（U+2026）或自定义 `<string>`。适用于除多列容器外的 block container；通常需同时设置 `overflow: hidden`，否则只加省略号而不裁剪。截至抓取时**非 Baseline**（主流浏览器未全部支持无前缀版本）。

兼容写法是带前缀的 `-webkit-line-clamp`，只在 `display: -webkit-box`（或 `-webkit-inline-box`）且 `-webkit-box-orient: vertical` 时生效。

## Key Takeaways

- `-webkit-line-clamp` 适合单一段落的纯文本摘要；它按"行数"裁剪，不理解不同行高的混合内容。
- 当预览正文由段落、列表项、任务行等行盒高度不一致的块组成时，"N 行 × line-height"的固定高度会切到半行；需要按真实 line box 计算可见高度。
- Searcher 两种做法并存：
  - `trash.css`、`ask-workspace.css` 的摘要使用 `-webkit-box` + `-webkit-line-clamp: 2`。
  - 首页笔记卡片 `HomeNoteCard.tsx` 不用 line-clamp：`Range.getClientRects()` 读取正文所有行盒，`clipPreviewHeight(rects, limit, scrollHeight)` 在 `--home-note-body-lines × line-height` 预算内停在最后一条完整行，写入元素高度，仅实际溢出时最后一行渐隐；`ResizeObserver` 与 `document.fonts.ready` 触发重算。见 [[concepts/whole-line-preview-truncation]]。
