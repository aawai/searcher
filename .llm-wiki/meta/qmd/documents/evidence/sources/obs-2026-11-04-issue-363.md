# ⭐ Observation: Issue 363 移动端刊头重设计方案与待决项

已向用户提出移动端（<768）方案并附 HTML 效果图（/tmp/m363/proposal/mobile.html，board.png/board2.png/veils.png，临时目录，未推送）：A 方案把搜索框常驻底部，与任务栏组成拇指区，位置由纯 CSS 决定，删除 searchRect/searchDock/--masthead-dock-shift；展开时搜索框不动；聚焦时上浮到顶栏下（FLIP 现场测量）；收起态去掉粗线，展开时粗线画出；刊头改为非模态，任务栏保持可用。B 方案为居中加无导语。用户质疑底部是否显得堆积（Via 自带底栏会叠出三层）；双方倾向收起态隐藏“继续编辑 / N 篇置顶”导语行，只留日期块和“时间 · N 项待办”。用户希望头部模糊淡一点：已渲染 V0 现状（blur 28 / 22-24%）、V1 减半（14 / 14%）、V2 轻纱、V3 无模糊、V4 只在日期块后做径向局部柔光；高对比条纹壁纸上 V2、V3 的星期不可读。建议把刊头衬底强度挂到已有的每张壁纸可读性档位（WALLPAPER_READABILITY_STAGES：无/清透/均衡/沉静/专注，src/shared/wallpaper-presentation.ts），目前衬底与该档位无关。底部或居中、契约“搜索框保持原锚点”的修改、平板窄屏的处理均待用户决定。尚未改代码。
