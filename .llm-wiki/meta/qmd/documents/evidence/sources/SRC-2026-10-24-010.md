# WAI-ARIA APG Combobox Pattern
> _Original: [https://www.w3.org/WAI/ARIA/apg/patterns/combobox/](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)_

## Summary

W3C ARIA Authoring Practices Guide 的 Combobox 模式：带弹出层（listbox / grid / tree / dialog）的输入控件。区分 select-only 与 editable；editable 又按自动补全行为分为四类：无自动补全（`aria-autocomplete="none"`）、列表手动选择（`list`）、列表自动选择首项、列表 + 行内补全（`both`）。搜索框建议属于"任意值 + 建议"场景：未选中建议时，输入的字符串就是值。

键盘契约：combobox 本身在 Tab 序列中，弹层及其后代不在；`Down Arrow` 进入弹层，`Escape` 关闭弹层（可选再按清空），`Enter` 接受选中的建议。listbox 弹层内上下移动并"选择跟随焦点"，左右键 / 可打印字符 / Backspace 把焦点交回输入框继续编辑。DOM 焦点始终留在 combobox，辅助技术焦点通过 `aria-activedescendant` 指向当前 option。

ARIA 属性：`role="combobox"`；`aria-controls` 指向弹层（仅可见时必须）；`aria-expanded` 反映弹层可见性；非 listbox 弹层需设 `aria-haspopup`；当前项 `aria-selected="true"`；用 `<label>` / `aria-labelledby` / `aria-label` 命名；ARIA 1.0 的 `aria-owns` 写法已不推荐。

## Key Takeaways

- 分组建议：listbox 内用带名称的 `role="group"` 包裹 option，但 `aria-activedescendant` 需要一条扁平的 option 序列（Searcher `OmniboxListbox` 注释："one flat option sequence for aria-activedescendant"）。
- APG 警告不要拦截浏览器原生文本编辑按键；Searcher 只占用 `Enter`/`Alt+Enter`/`Shift+Enter`/`Escape`，且输入法合成期间不响应，与此一致。
- APG 允许 `Escape` 分层：先关弹层再可选清空；Searcher 的逐层关闭（建议 → 菜单/弹窗 → 回答卡片）是该语义的扩展。
- Searcher `SearcherSearchInput` 使用 `aria-autocomplete="list"`、仅在打开时设置 `aria-controls` 与 `aria-activedescendant`，符合 APG。
