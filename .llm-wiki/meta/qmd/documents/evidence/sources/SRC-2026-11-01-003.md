## 摘要

rehype-sanitize 是一个 unified/rehype 插件，**丢弃 schema 未明确允许的一切**，默认对齐 `github.com` 的行为（第 206–208 行）。

DOM clobbering：用户内容里的 `id`/`name` 可能遮蔽全局或文档属性；rehype-sanitize 通过给所有 `id` 和 `name` 加 `user-content-` 前缀来避免（第 398–399 行）。代价是页内链接失效；README 给出的办法是像 GitHub 一样把友好链接重写到带前缀的元素（第 422–429 行）。

扩展：KaTeX/MathJax 等 rehype 插件依赖特定 class 并注入复杂标记与内联样式，默认会被大部分移除（第 484–489 行），需要自定义 schema 才能放行；放行即意味着放宽白名单。

安全：默认是安全的，但不当使用会引入 XSS；**应放在最后一个不安全步骤之后**——它之后的一切都可能不安全（第 633–639 行）。

## 关键要点

- 白名单模型，默认 GitHub 行为。
- `id`/`name` 前缀防 DOM clobbering，副作用是锚点链接需要重写。
- 插件顺序决定保护范围：sanitize 必须靠后。
- 为了放行 class 或样式扩展 schema 即放宽安全边界。
