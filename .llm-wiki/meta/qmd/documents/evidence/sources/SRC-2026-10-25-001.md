# A perceptual color space for image processing (Oklab)
> _Original: [https://bottosson.github.io/posts/oklab/](https://bottosson.github.io/posts/oklab/)_

## Summary

Björn Ottosson 2020 年提出的 Oklab 色彩空间（2025 年补记：已进入 CSS Color Level 4/5、Photoshop 渐变插值等）。目标是"简单、数值稳定、能较好预测感知 lightness / chroma / hue"的 opponent 色彩空间：坐标 `L`（感知亮度）、`a`（绿–红）、`b`（蓝–黄），D65 白点；极坐标形式 LCh（即 CSS 的 `oklch()`）中 `C = hypot(a, b)`、`h = atan2(b, a)`。

转换为两步：线性 sRGB → LMS（3×3 矩阵）→ 逐通道立方根 → 第二个 3×3 矩阵得到 Lab；逆变换为立方。作者以 CAM16 生成的等亮度 / 等彩度数据与 Ebner–Fairchild 等色相数据评估：CIELAB/CIELUV 的主要问题是色相预测差（蓝色混白时偏紫），CAM16-UCS 均匀性最好但数值行为差、不具尺度不变性；IPT 色相好但亮度 / 彩度差。Oklab 沿用 IPT 的计算结构、拟合到接近 CAM16 的亮度与彩度预测。

## Key Takeaways

- HSV 的等 value/saturation 色相环亮度很不均匀（黄、品红、青明显更亮）——按 HSV 色相分箱或固定 S/V 生成强调色会在不同色相上得到不同的对比度。
- Oklab 中 L、C、h 近似正交：固定 h、调 L 求对比度不会引起肉眼可见的色相漂移，这正是"保持色相、只解亮度"类算法所需的性质。
- Oklab 只保证感知均匀，不保证落在 sRGB gamut 内；高彩度 + 极端亮度需要 gamut mapping（常见做法：固定 L、h，降 C）。
- Searcher 的 `web/src/design-system/wallpaper-accent.ts` 直接内联 Oklab 正逆矩阵：像素转 OKLab 后按色相 24 箱、以 chroma × 亮度权重投票取主色相，再在 OKLCH 中固定色相、二分降低 chroma 至 sRGB gamut 内，逐步调整 L 直到满足 WCAG 对比度（见 [[concepts/wallpaper-accent-oklch-contrast-solver]]）。
