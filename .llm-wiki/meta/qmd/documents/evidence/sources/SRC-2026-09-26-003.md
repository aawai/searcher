# Hono Documentation: Fullstack Stacks & Architecture Patterns
> _Original: [https://hono.dev/docs/concepts/stacks](https://hono.dev/docs/concepts/stacks)_

## Summary

The Hono Stacks guide outlines modern architectural paradigms for constructing full-stack TypeScript applications with Hono. Rather than limiting the framework to isolated microservices or JSON backends, Hono provides end-to-end integration patterns combining HTTP servers, validation pipelines, and typed clients.

A core component is the Hono RPC pattern: by method-chaining route handlers on the server and exporting the inferred `AppType = typeof routes`, clients using `hc<AppType>` gain compile-time type-safety, auto-completion, and automatic payload deserialization without code generation or OpenAPI schema drifts.

Validation middleware (specifically `@hono/zod-validator` with Zod) sits at the boundary of incoming requests, verifying headers, query parameters, URL path parameters, and JSON request bodies before handing parsed data to type-safe handlers.

## Key Takeaways

- **End-to-End Type Safety**: Exporting route types directly allows client SDKs (`hc`) to auto-complete routes, request shapes, and response types with zero code generation.
- **Request Boundary Validation**: Declarative validators intercept malformed payloads before domain logic execution, enforcing contract boundaries.
- **Method-Chaining Contract**: For TypeScript to preserve route and method metadata across multiple endpoints, route definitions must be chained sequentially.
- **Full-Stack Cohesion**: Combines REST routing, middleware pipelines, and client typing into a single cohesive architecture.
