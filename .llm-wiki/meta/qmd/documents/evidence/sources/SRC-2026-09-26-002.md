# Hono Documentation: Getting Started with Deno
> _Original: [https://hono.dev/docs/getting-started/deno](https://hono.dev/docs/getting-started/deno)_

## Summary

This official guide demonstrates running Hono applications natively on the Deno runtime. Because Hono is built entirely upon standard Web APIs (`Request`, `Response`, `Headers`, and `Fetch`), it integrates natively with Deno without requiring Node.js compatibility shims or emulation layers.

The entry point leverages Deno's native HTTP server via `Deno.serve(app.fetch)`, which provides high-throughput request handling directly in the V8 isolate. For static asset delivery in monorepos or unified frontend/backend deployments, Hono provides `serveStatic` imported from `hono/deno`, allowing SPAs and assets to be served alongside REST APIs in a single process.

Deno's native TypeScript support, modern task runner, and unified security model eliminate the build step on the server, ensuring rapid development iteration and deterministic deployments to Deno Deploy or containerized environments.

## Key Takeaways

- **Native Web Standards**: Hono's `app.fetch` handler binds directly to `Deno.serve`, eliminating adapters and maximizing execution speed.
- **Unified Static File Serving**: Hono on Deno provides `serveStatic` from `hono/deno` for static assets and fallback HTML routing.
- **Zero-Build TypeScript Runtime**: TypeScript files execute directly without requiring separate transpilation or bundling pipelines.
- **Port and Config Customization**: Server port and binding options are passed straightforwardly via `Deno.serve({ port }, app.fetch)`.
