# MDN Content Security Policy (CSP)

原文：[MDN Content Security Policy (CSP)](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP)；证据：[不可变提取文本](../../raw/sources/SRC-2026-10-30-003/extracted.md)，第 217–242、250–323、582–717、774–893 行。第 334–581 行的 fetch directive 细节未纳入本页摘要。

## 摘要

CSP 通过响应头 `Content-Security-Policy` 下发，应设置在所有响应上，而非仅主文档；`<meta http-equiv>` 只支持部分特性，且 report-only 策略不能放在 `<meta>`。策略由分号分隔的指令组成。它的主要用途是控制可加载资源以缓解 XSS，其次是防点击劫持、升级不安全请求和要求 Trusted Types，四类用途互不依赖。MDN 明确：CSP 不是输入净化的替代，应与净化叠加作纵深防御。

推荐 strict CSP：用 nonce 或 hash 控制脚本，并加 `object-src 'none'; base-uri 'none'`，而不是 allowlist（allowlist 难写对、易含不安全域名、维护体量大）。nonce 适合动态生成响应；静态内容需 hash，但脚本改动后须重算。`'strict-dynamic'` 让被 nonce/hash 信任的脚本再加载的脚本继承信任，降低维护成本，同时削弱保护——若受信脚本依据 XSS 可控输入创建 `<script>`，CSP 不再拦截。启用 CSP 还需重构内联脚本、内联事件处理器、`javascript:` URL 和 `eval()`。

`frame-ancestors 'none'` 防点击劫持，是 `X-Frame-Options` 的更灵活替代；`require-trusted-types-for 'script'` 加 `trusted-types` 要求注入 sink 只接受经命名策略转换的 Trusted Types 对象。部署建议先用 `Content-Security-Policy-Report-Only`，违规报告首选 Reporting API（`Reporting-Endpoints` + `report-to`，`application/reports+json`），`report-uri` 已弃用但在 `report-to` 全面支持前建议同时声明。
