# Deno KV internals: building a database for the modern web

> _Original:
> [https://deno.com/blog/building-deno-kv](https://deno.com/blog/building-deno-kv)_

## Summary

本文深入剖析了 Deno 内置键值存储（Deno KV）的底层架构设计与存储引擎实现。Deno KV
的核心目标是提供零配置、强一致性且兼顾单机与分布式场景的现代数据持久化方案。在本地开发与单机部署环境中，Deno
KV 完全建立在 SQLite 存储引擎之上，利用 SQLite 的 WAL 模式与 B-Tree
索引实现了紧凑且可靠的数据持久化。

文章详细解释了 SQLite 在高并发读写环境下的并发控制模型：由于 SQLite
原生限制同一时刻只允许一个写事务（Single-Writer），Deno KV
通过内部协调器与原子事务流水线排队处理写请求，避免了 `SQLITE_BUSY`
数据库锁死风险。同时，系统在保证 ACID
特性的前提下，利用本地嵌入式数据库的零网络传输优势，实现了微秒级的本地键值查询与版本原子校验。

## Key Takeaways

- **SQLite 本地驱动基础**：Deno KV 在单节点环境直接使用嵌入式 SQLite
  作为底层存储引擎，依托 WAL（Write-Ahead
  Logging）模式实现并发读取与单写并发隔离。
- **写并发排队与原子性**：针对 SQLite
  单写限制，架构设计采用排队流水线统一协调事务提交，保证多协程并发写入时的线性一致性与非阻塞重试机制。
- **版本控制与乐观并发**：通过存储键值的版本时间戳与哈希向量，上层业务可以在无分布式锁的前提下实现原子性
  Check-and-Set（CAS）操作。
