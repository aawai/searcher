# Hono 中间件流水线与上下文生命周期指南

## Summary

本源文档是 Hono
官方关于中间件（Middleware）架构、洋葱模型调度与上下文传递的指南。Hono 基于原生
Web Fetch API 标准，将请求生命周期划分为前置处理（Before
Dispatch）、最终路由处理（Handler）与后置处理（After Dispatch）。

文档详细解析了通过 `await next()` 串联的洋葱执行模型，说明了早期中断（Early Exit
via Response）、上下文状态共享（`c.set()` 与
`c.get()`）以及全局异常拦截（`app.onError`）的设计原则。在
[[entities/searcher-项目]] 中，HTTP 服务端 [[entities/hono-framework]]
依托这套架构建立了由 [[concepts/hono-middleware-pipeline-request-intake]]
主导的安全防御与数据标准化管线，包括全站请求体大小限制、CSRF Origin
检查、结构化响应信封封装与统一输入校验。

## Key Takeaways

1. **洋葱调度模型**：按照注册顺序依次触发前置逻辑，在 `await next()`
   唤醒下游处理后反向执行后置拦截与响应头注入。
2. **异常穿透防护**：下游未捕获异常被框架自动收敛至应用级 `app.onError`，保证
   `await next()` 自身永不无故抛错中断后置清理。
3. **安全与协议防护网**：中间件能够在请求进入业务 Service
   之前完成身份凭证提取、Origin 跨站校验与 Body 尺寸硬限制。
