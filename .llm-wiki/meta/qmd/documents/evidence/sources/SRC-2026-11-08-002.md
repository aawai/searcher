# Authentication Cheat Sheet (OWASP)

原文：[OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)；[提取文本](../../raw/sources/SRC-2026-11-08-002/extracted.md)，正文第 301–746 行。同一 URL 在 2026-11-08 有一次中断的重复捕获（SRC-2026-11-08-001，提取为空），已作废，见 `meta/events.jsonl` 的 `discard` 事件。

## 摘要

本次只摘取与 Searcher 登录相关的三节：认证错误消息、自动化攻击防护、日志监控。

**错误消息与计时（第 444–537 行）**

- 登录、密码重置、找回密码必须返回同一条通用错误，不区分“用户名或密码错”“账号不存在”“账号已锁定或禁用”（第 450–454 行）。注册同样适用（第 456 行）。
- 处理耗时本身就是差异因素：用户不存在时提前返回，会让攻击者靠响应时间区分用户名错与密码错。应走同一条处理路径（第 460–490 行）。
- HTTP 状态码也可能泄露结果，即使页面文案相同（第 535 行）。

**自动化攻击（第 539–589 行）**

- 三类攻击：brute force（单账号多密码）、credential stuffing（泄露的账号密码对）、password spraying（单个弱密码试多个账号）（第 543–547 行）。单项防护都不完整，需要 defense-in-depth（第 549 行）。
- MFA 是最有效的防护（第 555 行）。
- **Account lockout**：失败计数应**挂在账号上，而不是来源 IP**，以防攻击者分散到大量 IP（第 569 行）。策略三要素是阈值、观察窗口、锁定时长（第 571–573 行）。可以用指数锁定代替固定时长（第 575 行）。设计时须防止被利用来锁死他人账号造成 DoS（第 579 行）。
- CAPTCHA 只是增加成本的纵深控制，不是预防手段；可在少量失败后才要求（第 583–585 行）。

**日志（第 591–597 行）**：所有失败、密码失败和锁定事件都应记录并审查。
