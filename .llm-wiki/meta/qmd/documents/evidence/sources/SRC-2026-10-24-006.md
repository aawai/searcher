# SQLite FTS5 Extension (Trigram Tokenizer)
> _Original: [https://sqlite.org/fts5.html](https://sqlite.org/fts5.html)_

## Summary

SQLite 官方 FTS5 文档。本次摄取聚焦 §4.3.4 trigram tokenizer：它把每个连续 3 个 Unicode 字符作为一个 token，使 FTS5 从"整词匹配"变为"任意子串匹配"，查询短语可命中行内任意位置的字符序列，不要求与完整 token 对齐。

trigram 支持 `case_sensitive`（默认 0，大小写不敏感）与 `remove_diacritics`（仅在 `case_sensitive=0` 时可设 1）两个选项。未开启 `remove_diacritics` 时，trigram 表还能用索引加速 `LIKE` / `GLOB`；`case_sensitive=1` 时只能索引 `GLOB`。

文档列出的硬边界：少于 3 个字符的子串在全文查询中**不匹配任何行**；`LIKE`/`GLOB` 模式中若没有连续非通配字符序列，则退化为全表线性扫描；带 `ESCAPE` 子句的 `LIKE` 无法使用索引；`detail=none|column` 可缩小索引，但全文查询不能含长度大于 3 的 token。

## Key Takeaways

- trigram 是 CJK 子串检索的正确选择：`unicode61` 会把连续汉字视作一个 token，"来源"无法命中"今天的灵感来源是散步"。
- 1–2 字符查询必须由应用层另行处理（Searcher 在 `DocumentsService` 中对 owner 的有效笔记做 `instr(lower(...))` 扫描，常量 `TRIGRAM_MIN_LENGTH = 3`）。
- 切换 tokenizer 需要重建虚拟表（Searcher 迁移 `0026_documents_fts_trigram.sql`：`DROP` → `CREATE ... tokenize='trigram'` → 回填），索引体积增大，回滚脚本恢复 `unicode61`。
- 已有 `documents_ai/ad/au` 触发器按表名引用，重建虚拟表后仍然有效。
