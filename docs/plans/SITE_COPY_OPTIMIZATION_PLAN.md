# 全站文案优化实施计划

状态：主要代码和文档已实施，聚焦测试及部分实页验收已完成；剩余未验证范围见 [文案实施清单](../audits/SITE_COPY_REVIEW.md)。

日期：2026-11-11。

## 1. 目标与边界

让用户能准确判断“这是什么、操作会发生什么、当前是否成功、失败后怎么办”。优先修正文案与行为不符，再统一领域术语，最后处理排版与冗余。

依据：

- [Visual Language · 文案](../design/VISUAL_LANGUAGE.md#文案)：当前术语与动作命名的唯一规范。
- [UI 验收清单](../design/UI_CHECKLIST.md#实页矩阵)：实页验证范围。
- [测试操作规范](../testing.md#验证调度)：验证调度、隔离与证据复用。
- [外观与同步](../appearance.md)、[AI 问答](../ai.md)、[应用](../apps.md)、[笔记](../documents.md)、[工作区](../workspace.md)：行为契约。

### 纳入范围

1. 生产页面与窗口：搜索首页、刊头、应用、笔记、AI 问答、设置、账户、登录与注册、管理后台、回收站、分享入口、404 与加载失败页。
2. 菜单、弹窗、字段标签、占位文字、说明、空状态、Toast、错误与恢复操作。
3. `aria-label`、`title`、图片替代文本、读屏状态播报及快捷键说明；可见文字与辅助文本一起核对。
4. 前端实际呈现的后端消息、共享显示元数据，以及生产使用的 HTML / PWA 静态文案。
5. 与上述文案直接冲突的输入限制、状态判断和安全确认边界。

### 不纳入范围

- 用户自行输入的名称、笔记正文、对话内容、模型原始回复，以及第三方品牌名、模型 ID、URL、代码、协议字段。
- 数据库字段、API 路径和 DTO 的全面重命名；不做历史数据文案迁移。
- CLI、诊断日志、测试 fixture、实验页面的全面润色。仅当共享字段调整影响这些消费者时同步迁移。
- 新增 i18n 框架、全站字符串中心、跨业务同步中心或错误平台。
- 改变权限、删除生命周期、临时对话保留策略、模型参数继承规则和上传额度产品策略。

产品代码、规范和 CHANGELOG 的实施与验证结果见文案实施清单；尚未验证的场景不标记为完成。

## 2. 前次盘点的校正

前次扫描属于候选发现，不是精确的用户可见文案统计：字符串、JSX 补充行、重复引用、后端消息及 fixture 混在一起。`/tmp/copy.txt` 不是可持续交付基线，不以“约 2,400 条 / 151 个文件”作为覆盖率或完成依据。

| 原判断                                | 核对后的处理                                                                                                                                                |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 8 项全部属于 P0                       | 分为行为错误、命名错误、维护债；不把所有文案差异等同于紧急缺陷                                                                                              |
| 登录框只需更名                        | `AuthPage.tsx` 登录与注册共享用户名长度属性，登录也有 `maxLength={usernameRules.maxLength}`；服务端登录支持邮箱。必须同时检查长邮箱可输入性，不能只改标签   |
| 删除确认只是不统一                    | 此计划编写后现行实现及 CHANGELOG 已改为只接受不带 `@` 的用户名；实施以现行契约为准，不恢复 `CONFIRM`                                                        |
| “恢复预设 / 重置”可以合并             | `GenerationSettings.tsx` 的 `handleResetCurrent` 清除当前采样 / 长度覆盖，`handleResetDefaultAction` 调用清除已保存默认配置的回调；必须区分范围，不合并动作 |
| 主题长短名称重复                      | `appearance.md` 明确规定主题图块用短标题、读屏用完整名称；保留这组有意差异                                                                                  |
| 已登录即可显示“已同步”                | `SettingsPage.tsx` 确实仅按 `user` 判定；外观、任务栏、笔记有独立保存状态，不可用一个外观失败布尔值推导全站已同步                                           |
| 所有流错误统一成“回答中断，请重试”    | 保留鉴权、模型不可用、限流、网络中断、无效响应等可执行差异；不得掩盖原因或承诺必然可重试                                                                    |
| 所有租约提示统一成“即将过期”          | 无法续期、已经过期和无法恢复不同；去掉“租约”术语，但不能把未知或已过期状态说成即将过期                                                                      |
| 强调色 description 无 UI 引用即可删除 | 已核对声明与仓库消费者；无消费者读取该字段，移除描述，不改变色值和名称                                                                                      |
| 恢复一律留给回收站                    | 历史版本恢复、窗口还原、备份还原分别有自己的对象；采用“动作 + 对象”，不禁用其他合法的“恢复”                                                                 |

`UI_CHECKLIST.md` 与 Visual Language 原先对“登录后可用”类提示的规则存在冲突。用户已确认按场景保留必要说明；简单字段也可保留简短输入提示，独立标签和持久格式说明不变，规范已对齐。

## 3. 不变量与目标用词

### 不变量

- 文案不能承诺尚未完成的保存、同步、恢复或生成，也不能在失败时丢弃当前输入。
- “移至回收站”只用于真实进入回收站的对象；永久删除须说明不可恢复；用户软删除不伪装为回收站操作。
- 说明涉及外发数据、费用、覆盖方向、设备退出和本地草稿丢失时，不因追求简短而删除后果。
- 普通用户的错误不能泄露其他用户资源是否存在、密钥、内部路径或第三方原始响应中的敏感信息。
- 可见操作名与无障碍名称语义一致；允许辅助文本补充对象、作用范围与快捷键。
- 文案中的限制来自同一业务常量，前后端执行边界一致；不同用途的图片限制不合并。

### 目标词表

以下为实施默认方案；现有规范已定义的用词沿用，新条目在阶段 A 写入规范。

| 概念             | 目标用词                                         | 保留的区别                                                          |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------------- |
| AI 服务提供方    | AI 服务商；上下文明确时用“服务商”                | API / 类型名仍为 Provider；API Key、Base URL 等配置字段保留技术名称 |
| AI 交流记录      | 对话、临时对话、对话内搜索                       | 登录设备与认证会话不做全库字符串替换                                |
| 身份             | 账户、显示名称、普通用户、管理员                 | 登录标识明确写“用户名或邮箱”；注册仍为“用户名”                      |
| 首页固定         | 固定到首页 / 取消固定                            | 任务栏用“固定到任务栏 / 取消任务栏固定”；笔记收藏独立               |
| 首页固定笔记区域 | 固定笔记、N 篇固定笔记                           | 区域名称与动作关联，但不改刊头布局与排序                            |
| 笔记无标题       | 无标题笔记                                       | “正文为空”是内容状态；正文首行推导标题的既有逻辑不变                |
| 笔记归组         | 移动到笔记本                                     | 移动笔记本本身仍叫“移动笔记本”                                      |
| 数据动作         | 移至回收站、恢复、彻底删除、还原备份、恢复此版本 | 按对象与后果命名，不能机械替换“删除 / 恢复”                         |
| AI 搜索工具      | 搜索笔记、搜索应用、联网搜索                     | 管理配置和必要技术详情可标明 SearXNG                                |
| 当前生成参数     | 重置当前参数                                     | 与“清除已保存默认参数”“设为该模型默认”区分；说明最终继承来源        |
| 打开位置         | 打开方式；当前标签页 / 新标签页 / 跟随全局       | “打开设置”仅用于前往设置的动作                                      |
| 空间名称         | 应用窗口、笔记窗口、首页、任务栏                 | 不将内部“应用库”实现名自动替换成公开路由或 API 名                   |

### 排版规则

- 普通中文 UI 使用中文冒号、括号与引号（“”）；加载 / 进行中使用 `…`，不混用 `...`。
- 中文与 Latin 单词、阿拉伯数字之间按语境留空格；单位如 `2 MiB`、`20 mm` 保留单位前空格。日期、计数和品牌遵循对应格式，不用全库正则强行插空格。
- 二进制文件上限标为 MiB；不要仅把真实十进制 MB 的字符串替换成 MiB。
- 按钮短语不加句号；完整说明句使用中文标点；避免成功提示中的感叹号。
- URL、模型 ID、命令、代码示例、协议原文、用户数据不受中文标点替换影响。
- 技术设置使用准确术语与必要解释，不把所有技术信息删除。例如 Temperature 保留字段含义，不将“随机性低”承诺为“事实更准确”。

## 4. 阶段 A：建立可执行清单与规范

### 工作

1. 从当前 revision 的生产入口出发建立文案清单，不直接沿用临时扫描数量。补查纯英文 UI、跨行 JSX、模板字符串、HTML / manifest 与运行时拼接消息。
2. 每项记录：文件与符号、页面 / 角色、触发状态、原文、目标文案、变化类型、行为依据、现有覆盖、验收结果。相同字面但不同含义分项记录。
3. 区分用户可见文案、仅 API 消费者可见的校验错误、日志、测试数据和实验展示；源码命中不等于生产可达。
4. 将第 3 节的新增规范落到 Visual Language；提交 UI_CHECKLIST 冲突的对齐建议，不自行改变验收政策。
5. 核对高风险字段、导出符号及消费者；有语言服务时使用引用查询。动态字符串和解析不确定项人工核对，不把抽取器猜测当成结果。

### 交付与出口

- 在 `docs/audits/` 保存本次实施清单与覆盖索引；行号只是导航，文件 / 符号 / 状态才是稳定定位。
- 所有纳入范围的表面均有记录或“无需变更”的依据；没有仅靠扫描数量宣称全站完成。
- 新措辞已有规范依据；规范 / 验收政策冲突已有明确决定后，相关批次才进入实施。

## 7. 阶段 D：错误文案与恢复路径

不构建新的全局错误框架，沿用现有边界与响应结构。先追踪前端如何消费消息，再在最接近业务原因的地方改写；不得依赖中文字符串匹配错误类别。

| 场景                      | 文案必须表达                                             | 保持的行为                                                                         |
| ------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 服务连接或流中断          | 哪个操作未完成；当前内容是否保留；有现有重试操作时指向它 | 区分主动停止、网络中断、协议异常；不虚构“继续生成”能力                             |
| 鉴权 / 限流 / 模型不可用  | 重新登录、稍后再试或选择其他模型等对应动作               | 不把所有错误统一成网络故障                                                         |
| 临时对话续期失败          | 暂时无法保留，提示检查网络与复制重要内容                 | 不声称已经过期，也不保证离线无限保留                                               |
| 临时对话已过期 / 无法恢复 | 准确说明当前已无法恢复，提示复制仍可见内容               | 不声称复制可恢复附件或完整历史                                                     |
| 上传限制与格式错误        | 对象、允许格式、实际业务上限                             | 图标 / 壁纸 / 笔记 / AI 附件分别处理                                               |
| 笔记冲突 / 保存失败       | 本地修改状态、云端覆盖方向与当前可用恢复选项             | 保留草稿、二次确认及失败不丢内容的不变量                                           |
| 管理端配置与还原失败      | 可操作原因和必要技术字段                                 | 不在普通用户提示中透出密钥、内部路径或原始敏感响应；管理员的必要诊断保持受权限约束 |

API-only 的类型 / schema 报错不强行改成口语。技术配置页允许保留 Provider 发现来源、协议名等诊断概念的准确解释；普通操作面不直接倾倒异常对象。

阶段出口：人工构造代表失败状态，逐条确认“消息属实、下一步存在、内容未丢失、权限未泄露”；后端成功消息只在确实被 UI 展示时纳入前端措辞验收。

## 8. 阶段 E：排版与冗余清理

1. 对已确认的生产文案应用排版规则，同时迁移 Tooltip、读屏名称和现有行为测试定位。
2. 不用全库正则修改 URL、协议原文、命令、代码、用户数据和示例片段；模板字符串只修改静态文案部分。
3. 压缩冗长说明，但保留风险信息。例如网址变更确认同时说清“重新获取图标并保存”，取消则保留表单不保存。
4. 对重复提示先检查是否属于不同呈现方式或不同状态；不因字符串重复就删除 UI 分支。
5. `AccentMeta.description` 仅在全引用核对后确认为未使用且无外部契约时删除。若仍被展示，改为客观颜色描述，移除“护眼”等无依据宣称，不删除配色数据。

### 自动检查边界

本计划不把新的标点扫描直接升级为 CI 阻断项。现有 `check:ui` 继续执行。

先用一次性语法感知抽取辅助核对，人工检查误报：必须跳过注释、URL、代码、协议及用户内容，也要发现跨行 JSX。只有规则稳定、例外边界明确且验收政策经人类确认后，才单独接入持久检查。不能新增“CJK 旁出现半角括号就失败”一类粗粒度门禁，也不建立逐字符串快照测试。

## 9. 验证与验收

### 行为验证

- 先查现有覆盖：图标路由已有 `src/features/webapp-icons/webapp-icons.route.test.ts`；认证与 UI 入口包括 `web/e2e/auth.test.ts`；状态相关覆盖包括 `web/src/app/state.test.ts`；AI / 设置覆盖包括 `web/e2e/ai-window.test.ts`、`web/e2e/settings-shortcuts.test.ts`。实施时按当前脚本与实际职责继续定位，不假设这些文件已覆盖全部边界。
- B1–B6 的验收条件逐项证明。已有覆盖优先迁移；新增测试仅保护可观察的边界、状态转移或权限，不为标点和固定文案写源码断言。
- 生成参数两种重置分别验证影响范围；临时对话、冲突、删除 / 撤销和备份还原保留原有行为覆盖。
- 测试中作为交互入口的 role / accessible name 跟随最终产品文案更新；纯措辞快照或实现细节断言删除，不重新锁定无意义的新文本。
- 测试只操作隔离数据库、假服务商与测试账户，不在真实账户执行删除、还原或付费生成。

### 实页验证

| 表面                         | 必验内容                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------- |
| 访客首页 / 设置、登录 / 注册 | 不出现账户数据上云的错误承诺；用户名 / 邮箱与注册规则区分；长提示换行与错误聚焦 |
| 登录首页、应用与任务栏       | 固定位置区别、菜单与确认措辞、图标边界提示、占位文字与预览一致                  |
| 笔记与回收站                 | 长标题、无标题与空正文、移动对象、冲突、未保存草稿、恢复与彻底删除              |
| AI 与 AI 设置                | 推理两档可区分、不同范围的重置、临时对话提示、无模型的角色差异、生成失败与取消  |
| 账户与管理后台               | 密码边界、退出设备、删除确认接受值、系统配置导入与备份覆盖后果                  |
| 全局错误 / 分享 / 404        | 可达操作、状态反馈、无障碍名称与实际行为一致                                    |

按 UI_CHECKLIST 的局部验证规则，选窄视口和窄 Host 检查长文案、换行、裁切、按钮与键盘焦点；补一个正常桌面宽度。仅文案变化不机械跑所有主题 / 壁纸组合；若实施改到共享布局、状态样式或几何，按现行规则扩大矩阵。批量视觉证据记录角色、视口、Host、主题、触发状态及选择依据，逐张审阅。

### 执行顺序与证据

1. 行为修改先运行最近的现有测试；缺覆盖时执行 Contract → Red → Green。
2. UI 修改执行 `deno task check:ui`，按上述范围完成实际页面操作与截图；类型或导出变更增加对应 typecheck。
3. 浏览器操作前遵守测试调度规则；E2E 首轮使用 `--timeout 5000` 或 `E2E_TIMEOUT_MS=5000`。失败归类后只复查受影响范围，限时全部通过可按现行规范复用。
4. 构建产物不在验收运行中替换；各进程隔离服务、数据库与报告目录。完整门禁可复用同 revision 有效 CI 证据，不用局部通过宣称 full 通过。
5. 文档 / 链接调整使用定向链接检查；触及 AGENTS 的引用事实时核对对应章节并执行 `deno task check:agents`。单纯计划文档不触发产品 E2E。

## 10. 合并、回滚与完成定义

### 合并顺序

A 规范与清单 → B 各独立行为增量 → C 领域迁移 → D 错误与恢复 → E 排版清理。C / D 可按不重叠文件分工，但依赖的行为边界必须先确定；同一文件不并发修改。各增量携带自己的文档与验证证据，不把文档更新集中拖到最后。

### 回滚

- 每个增量把代码、相关文档与测试选择器一起回滚，不保留新旧措辞兼容层。
- 本计划不涉及数据库迁移或已有用户内容重写，回滚不应要求数据恢复。
- 不回退其他人的未提交修改；发现同文件变化时按当前实现重新核对范围。
