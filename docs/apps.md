# 应用

应用（webapps）是登录用户保存的网址快捷方式，可分组到文件夹。资料库应用视图持有全部应用与文件夹，首页只显示固定到首页的根级子集，承载日常启动与拖动整理；两者消费同一份应用库与顺序，不维护第二张桌面。

## 首页应用库

登录后首页搜索框下方的 Material 底板只显示**固定到首页**的根级图块（应用与文件夹）。根级 `sortOrder` 与文件夹成员顺序是唯一顺序：首页顺序即已固定根级项按 `sortOrder` 的子序列，首页拖动排序改写该子序列在全库顺序中的相对位置。

### 固定到首页

- 根级应用与文件夹各自有固定状态（`webapps.is_home_fixed` / `webapp_groups.is_home_fixed`，默认关闭）。文件夹成员随文件夹整组显示；成员自身的固定状态在文件夹内不生效，移出文件夹或删除文件夹释放后继承原文件夹的固定状态。
- 首页右键、长按或 Shift+F10 菜单对已固定项提供“取消固定”；资料库应用视图的同一菜单对根级应用与文件夹提供“固定到首页 / 取消固定”。取消固定只影响首页呈现，应用仍在资料库，可从资料库或搜索建议打开；删除仍为“移至回收站”。
- 新建：首页空白处或文件夹弹层中的“+”新建应用默认固定；从资料库“添加应用”入口新建默认不固定，添加表单中的“固定到首页”开关可覆盖。首页新建文件夹（含把一个应用拖到另一个应用上）默认固定；资料库新建文件夹默认不固定，可在文件夹菜单中固定。
- 从首页“+”在文件夹内新建的应用属于该文件夹，首页呈现随文件夹；其自身开关不改变首页呈现。
- 固定操作不设上限；首页有效行数放不下的已固定项收进末格“更多（N）”，N 为未显示的已固定项数。

- 图块有三种：应用；小文件夹（与应用图标同尺寸，2×2 迷你图标预览）；大文件夹（占 2×2 格，正方形表面边长为格宽 + 间距 + 图标宽，左右对齐两列图标外缘、上边对齐首行图标，名称位于第 2 行应用名称基线且不占表面高度）。
- 图标固定桌面 48px / 移动端 44px；保留原标准网格：普通桌面格宽 84px、间距 12px，移动端 64px / 6px；粗指针沿用原 88px 桌面格宽、68px / 4px 移动格宽与间距。行高等于格宽，纵横间距相等，隐藏名称不改变方格；列数按底板内容区实测宽度计算，不再按底板外宽计算。
- 大文件夹无论成员数与指针类型，一律为 3×3 预览格位：成员 ≤9 个时从左上依次填充，其他格位留空，空文件夹保留空状态图标；>9 个时前 8 个为应用图标，第 9 格为剩余应用的迷你 2×2 预览，可访问名称为“打开文件夹 <名称>，另有 N 个应用”。精细指针可直接打开预览应用；粗指针下迷你图标不单独命中或进入 Tab 顺序，点按整块表面的任意位置打开文件夹，目标 ≥44px。
- 首页文件夹（大、小）使用磨砂材质底，随“玻璃效果”档位变化；关闭玻璃效果或系统开启“减少透明度”时为实色。应用图标、文件夹预览、“+”和“更多（N）”共享 1px 内环与极淡投影；操作块使用 Material 底与次要文字色字形，不使用灰底。
- “显示应用名称”统一控制首页网格、文件夹弹层与资料库应用视图内的应用名和大 / 小文件夹名；关闭时保留可访问名称与文件夹 title，表面几何不变。
- 首页网格位于与搜索框同宽的 Material 底板中，最大宽 `--layout-home-content-max`（<1024px 为 640px；≥1024px 为 `clamp(640px, 40vw, 880px)`，1440 下 640px、1920 下 768px、≥2200px 为 880px），圆角 `--radius-lg`（16px）；≥768px 内边距 `--space-4`（16px），<768px 全宽且内边距 `--space-2`（8px）。格宽、间距与图标保持 84 / 12 / 48（移动 64 / 6 / 44），列数随底板内容区增加：1440 下内宽 608px（6 列容量）、1920 下 736px（7 列）、2560 下 848px（8 列），网格在底板内水平居中；390px 移动端内宽 342px，5 列需 344px，故为 4 列，430px 起为 5 列。
- 底板内名称直接使用表面前景色，不加逐项胶囊、不依赖壁纸文字光晕。底板背景、模糊与阴影只取全局玻璃档位 Token；关闭玻璃效果或减少透明度时为实色、无 blur，边缘保留。
- 列数平衡在现有回填算法外层进行：只有容量列的末行只剩 1 格时才收窄列数，在不增加已需行数、不超过有效行数的前提下选择能使末行至少 2 格的最少列数，避免单独的“+”或单图块末行。19 格 / 上限 6 列（6 + 6 + 6 + 1）改为 5 列 × 4 行（末行 4 格）；12 格 / 6 列与 7 格 / 5 列的末行已有 ≥2 格，保持原列数。含 2×2 大文件夹时不做列数平衡，保持其足迹、回填与“更多”预留规则。
- 不显示悬浮省略号按钮或图标下方的左右移动按钮。

### 容量与“更多”

有效行数 = clamp(1, 4, floor((布局视口高度 − 网格内容区顶 − 底板下内边距 − 48) / 行距))；网格顶已含底板的上内边距（整理时也含整理条），底板下缘距视口底边保留 48px，不能只测内部网格。1440×900 为 4 行，1366×768 只有 3 行（4 行会留下不足 48px），第 4 行由“更多（N）”承接；矮屏自动降行并将超出内容收入“更多”，搜索框的 38% 锚点不因降行改变。容量以布局视口高度计算，软键盘弹出不重排，窗口尺寸变化时重算。

- 超出有效行数的已固定图块收进末格“更多（N）”，N 为未显示的已固定图块数；大文件夹按 2×2 计位，有效行数为 1 时进入“更多”。
- 点击“更多（N）”打开资料库应用视图，不再展开独立弹层；该视图显示全部根级图块并提供“添加应用”，因此超出容量时首页不再单独显示“+”。
- 文件夹仍以 Floating 材质弹层展开，锚定底板上缘，触屏同样可用；Escape 关闭弹层，焦点回到触发图块。
- DOM、Tab、方向键与读屏顺序按视觉位置（行优先）排列，整理模式下键盘移动也按视觉顺序进行，并换算回规范顺序。

### 就地管理

- 右键应用图标（触屏长按；键盘菜单键或 Shift+F10）打开菜单：编辑、固定到首页 / 取消固定（按入口与当前状态）、移入文件夹、移出文件夹、删除。
- 文件夹菜单支持打开、固定到首页 / 取消固定（按入口与当前状态）、改名、大小与删除；删除文件夹不删除成员，成员回到根级末尾并继承文件夹的固定状态。
- 应用表单以会话隔离：有未保存修改时，关闭弹窗或应用内离开均先经过确认；路由离开由 blocker 裁决，仅 dirty 会话注册浏览器离开提示。
- 自动生成的名称不覆盖用户手动输入的名称；网址变化后的过期响应被忽略。
- 图标区默认折叠，校验错误时自动展开；“更换图标”进入图标编辑。
- 创建应用不等待网站图标请求；未取得图标也可立即保存。新增和现有的默认图标、缺少网站图标的应用自动逐个补全，同一会话每个应用最多尝试一次；沿用 `/api/webapp-icons/fetch` 的真实网站图标抓取与缓存流程，不使用字母图标代替抓取结果。
- “补全图标”可重试缺失图标，显示当前进度和失败数量；失败保留应用与原图标。补全不会覆盖上传、图片 URL 或 AI 图标；请求期间用户更改网址或图标时，忽略旧结果。单个补全请求为 `POST /api/webapps/:id/fetch-icon`，仅作用于当前账号未删除的应用；外部抓取在数据库队列外执行，写入前再次核对网址与图标。
- 来源依次为接近 180px 的 apple-touch-icon → manifest（优先较大候选）→ 页面 favicon → `/favicon.ico`。所有候选失败才保留域名色相首字母；颜色不随路径、名称或主题变化，字重 400，文字对比度 ≥ 4.5:1。
- 抓取、上传与 AI 图片先校验/清理，再在服务端解码为 256px PNG。完全不透明正方形铺满；透明或半透明边缘的图形放在白色画布上，每侧约 20% 留白。不再在浏览器重复加内边距；旧缓存图标首次读取时以相同规则升级。

### 空白处菜单与整理模式

应用网格的空白处右键、键盘菜单或触屏长按，菜单提供“新建文件夹”和“整理布局”；空白面保留正常触屏滚动。

整理时菜单改为“完成整理”并禁用“新建文件夹”，同时隐藏添加入口。

- 应用拖到文件夹为归组；根级图块拖拽为混排排序；文件夹内拖拽仅改变成员顺序。
- 失败回滚并显示错误。
- 根级混排以单次 `PUT /api/webapps/reorder` 的 `{ items, groups }` 原子保存；成员移入与移出追加到目标末尾。
- 布局保存在服务端快照确认后才采用；失败时提示可关闭，且不把旧数组覆盖到更新的排序上。退出整理不终止已发出的保存；布局缓存与保存按账号隔离。

### 搜索

首页搜索建议匹配应用名称或网址返回去重后的应用，匹配文件夹名返回文件夹，选中文件夹即在首页打开该文件夹。应用建议不限固定状态：未固定到首页的应用仍可通过建议打开。资料库应用视图另提供完整库搜索，见下文。

### 在首页显示应用

登录用户的跨设备偏好 `showHomeApps`（默认开启；访客没有应用，不显示该项），位于“设置 → 外观”。

- 关闭后首页不渲染应用底板、网格、“+”与“更多”；搜索框纵向位置不变，首页纸张默认落点不再避让应用区域，已保存位置的纸张不移动。开启但没有应用时底板只含“+”。
- 应用仍可通过搜索建议（应用与文件夹）打开；聚焦空搜索框时快捷入口显示“应用”，打开资料库应用视图，成为关闭首页网格后的完整应用管理入口。开启时该快捷入口不显示；资料库根视图始终保留“应用”入口。

### 旧数据迁移

迁移 `0029` 为 `webapps` 与 `webapp_groups` 增加 `is_home_fixed`（默认关闭），并把升级时未删除的根级应用与全部文件夹设为固定，升级前后首页外观不变；文件夹内应用与已删除应用保持默认关闭，不单独固定。应用、文件夹与顺序均不删除。回退只需恢复前端读取全部根级图块，新增列可保留。

## 资料库应用视图

- **定位与入口**：资料库根视图的“应用”、`/apps`、首页“更多（N）”与关闭首页应用后的空搜索框“应用”快捷项打开此视图。它是管理视图而不是第二张桌面。
- **完整性**：文件夹与未归组应用按应用库顺序混排在同一网格，包含空文件夹、超出首页容量的应用及未固定项；不设首页行数或容量上限。固定状态只影响首页呈现，不改变这里的顺序与成员。
- **复用外观**：使用首页同一套 `WebAppGlyph` 与文件夹图块、统一边缘及几何规则，不重做一套列表图标。应用名与文件夹名遵循 `showAppLabels`，隐藏时保留可访问名称。
- **文件夹导航**：文件夹在资料库内原地展开，返回恢复触发图块的焦点与原滚动位置；不另外打开一张桌面。
- **搜索**：顶部搜索按应用名 / 网址匹配并去重应用，按文件夹名匹配文件夹；结果分“文件夹”“应用”两组，可搜索文件夹内的应用。
- **操作**：点击应用启动；图块菜单复用 `AppMenuItems`，提供固定到首页 / 取消固定（仅根级应用；成员随文件夹）、编辑、删除（移至回收站）、移到文件夹 / 移出文件夹。文件夹菜单提供打开、固定到首页 / 取消固定、改名、大小、删除（不删除成员）；空白面菜单提供“新建文件夹”；“添加应用”为视图头部唯一主操作，新建的应用默认不固定，可在表单中打开“固定到首页”。
- **唯一整理位置**：资料库不提供拖动排序、键盘改序或旧版“整理布局”模式；顺序与位置的拖动整理仅在首页进行。管理操作复用现有布局持久化结果，新增、改名、删除与归组后两处显示同一数据，不新增第二套排序状态。
- **面板行为**：开合、焦点、Escape、未保存修改保护与账号清理由 [资料库](workspace.md#资料库) 统一拥有。

## AI 生成图标

添加或编辑应用时，在“图标 → AI 生成”选择图片模型、图片生成协议和风格。Provider
配置见 [AI](ai.md)。

### 协议

| `imageProtocol`              | 端点                                   | 请求                                               |
| ---------------------------- | -------------------------------------- | -------------------------------------------------- |
| `openai`（默认，省略时使用） | `/images/generations`                  | `n: 1`、`size: "1024x1024"`                        |
| `gemini`                     | `v1beta/models/:model:generateContent` | `responseModalities: ["IMAGE"]`，解析 `inlineData` |

- 仅当服务商支持 Gemini 原生接口时选择 `gemini`。协议仅用于本次图片请求，不修改
  Provider、文本模型配置、模型发现或聊天 SSE。
- Gemini 原生接口从 Base URL 去掉末尾 `/v1`、`/v1beta` 或对应的 `/openai`
  后缀，保留代理前缀；模型 ID 仅去掉原生 `models/` 前缀，不推断命名空间。Google
  官方域名使用 `x-goog-api-key`，其他代理沿用 Bearer。

### 发送内容

- 风格：极简、几何、符号、线性、双色、柔和渐变、柔和 3D、图形角色。
- 应用名称必填；域名从应用网址提取且只发送 hostname，不发送路径、query 或
  fragment。
- 可选“用途”最多 300 字，仅用于本次生成，不保存为应用字段。
- 生成前展示
  Provider、模型、图片协议、风格及实际发送的名称、域名和用途；取消不发起请求。

### 生成与结果

- 每次生成发起三个独立的单图请求；请求可能产生 Provider 费用。
- Prompt
  以已知官网/品牌图标的核心视觉语言为身份基线，要求单张画布只展示一个图标，并约束
  32 / 48 / 64px 可读性、单焦点、安全边距和候选差异；实际效果取决于 Provider /
  模型。
- 选中候选后沿用上传与图片校验流程，文件上限 2 MiB。
- 单次上游请求超时 60 秒；失败详情遮蔽当前 Provider 的 API Key。
