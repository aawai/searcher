# Searcher 前端实现指南

> 文档用途：指导 Searcher v1 的前端 UI、交互、状态管理、响应式布局、异常处理与前后端边界实现。  
> 本文以已确认需求为准；未在本文中定义的能力不应自行扩展为 v1 必需功能。  
> UI 基础组件必须优先使用 **shadcn/ui**，图标建议使用 Lucide；拖拽/排序等 shadcn/ui 不直接提供的能力可使用专门库实现，但最终视觉和交互应与 shadcn/ui 体系一致。

---

## 1. 产品定位

Searcher 是一个 **Search First 的中文个人搜索主页 / 起始页**。

首页的第一视觉焦点始终是搜索框。个人内容（Web App、便签）围绕搜索存在，但不能让首页演变成传统 Dashboard。

### 1.1 五条核心设计原则

1. **Search First**  
   搜索框始终是首页第一视觉焦点。

2. **Personal, not Dashboard**  
   收藏、便签、设置属于搜索主页的辅助能力，不能抢占搜索框的主视觉地位。

3. **Local-first Deployment**  
   核心功能基于 Deno + SQLite + 本地文件即可运行，不依赖第三方云基础设施。

4. **Explicit AI**  
   AI 问答必须由用户明确切换进入，不得在普通搜索中自动介入或替换搜索结果。

5. **No Silent Data Loss**  
   草稿、版本冲突、同步失败、登录会话失效时，不得静默覆盖或丢弃用户内容。

### 2.1 UI 组件库

- Dropdown Menu

- Dialog

禁止为了简单按钮、弹窗、菜单、Tab、Toast 等重新实现一套风格不一致的基础组件。

### 2.2 允许使用的补充能力

shadcn/ui 不直接负责的能力可以使用独立库：

- FTS5、SSE 等属于后端或数据层，不由 UI 库承担。

所有补充组件必须：
- 继承 Searcher Design Token；
- 与 shadcn/ui 的圆角、边框、阴影、焦点环保持一致；
- 支持键盘操作；
- 不得生成与主界面明显割裂的视觉风格。

## 5. 响应式与尺寸

### 5.1 搜索主区域

不要使用固定 720–840px 宽度。

Desktop 建议：

```css
width: clamp(680px, 52vw, 1080px);
```

目标：
- 1080p：保持集中；
- 2K：自然放大；
- 4K：最多约 1080px，不无限拉伸；
- 超宽屏主要增加留白而不是无限放大搜索框。

Mobile：

```css
width: calc(100vw - 32px);
```

### 5.2 垂直位置

搜索主区域位于视口高度约 30%–35%，不要严格居中。

目的：
- 下方为 Web App 与固定便签保留空间；
- 首页打开后搜索仍然第一眼可见。

### 5.3 搜索框圆角

圆角属于 Style 的一部分：
- Default：中大圆角；
- Minimal：偏小；
- Soft：较大；
- Glass：较大；
- Capsule：允许完整胶囊化。

不可把胶囊化写死为唯一样式。

## 8. 搜索框

## 8.1 普通搜索模式

Desktop 逻辑结构：

```text
[Engine ▼] [ Search Input                              ] [Search]
```

视觉上可将按钮整合在同一容器。

搜索引擎：
- Google
- Bing
- 百度
- DuckDuckGo

### 8.2 搜索引擎选择器

常态仅显示：
- Logo；
- 小型下拉箭头。

展开后显示：

```text
Google       ●
Bing         ●
百度         ●
DuckDuckGo   ●
────────────────
重新检测
设为默认
```

圆点：
- 绿色：当前设备最近一次资源连接检测成功；
- 红色：最近一次检测未成功。

不得显示“搜索服务正常/异常”等结论。

### 8.3 当前设备可达性

约束：
- 检测完全在浏览器执行；
- 服务端不参与；
- 结果存 IndexedDB；
- 不同设备结果独立；
- 检测是启发式资源连接检测；
- 不等价于搜索服务可用性。

建议记录：

```ts
{
  engineId,
  reachable,
  checkedAt,
  latency
}
```

菜单主视图只显示红/绿点。

Tooltip/详情可以显示：
- 最近检测时间；
- 耗时。

### 8.4 重新检测

底部“重新检测”：
- 并发检测所有启用引擎；
- 检测期间显示 Spinner；
- 完成后更新 IndexedDB。

允许针对单个搜索引擎重新检测。

### 8.5 默认搜索引擎与临时切换

用户在首页临时切换引擎：
- 只影响当前搜索；
- 不自动修改默认引擎。

只有：
- 设置页修改；
- 或菜单中明确“设为默认”

才改变默认值。

## 9. 搜索行为

### 9.1 URL Template

默认搜索引擎通过 URL Template 执行搜索。

例如：

```text
https://www.google.com/search?q={query}
```

前端提交前：
- URL encode query；
- 不允许危险协议；
- 不在客户端执行字符串脚本。

### 9.2 打开方式

用户偏好：
- 当前页；
- 新标签页。

快捷行为：

```text
Enter
  → 按用户默认设置

Ctrl/Cmd + Enter
  → 强制新标签页
```

### 9.3 键盘快捷键

至少支持：

```text
/
  聚焦搜索框

Ctrl/Cmd + K
  聚焦搜索框

Esc
  关闭弹窗 / 退出当前轻量编辑状态

↑ / ↓
  导航搜索引擎、模型、建议菜单

Enter
  搜索 / 发送
```

输入框正在编辑文本时，应避免 `/` 被错误拦截。

## 11. 搜索建议

v1 接入：
- Google 搜索联想能力；
- Bing 搜索联想能力；
- 本地搜索历史（用户开启后）；
- Web App 名称与 URL 匹配。

要求：
- 搜索联想能力做成 Adapter；
- 第三方联想失败时静默降级；
- 联想接口不可用不能阻断搜索；
- 不应把第三方联想失败展示成全局错误。

建议展示顺序：
1. 本地高相关结果；
2. 当前引擎联想；
3. Web App 匹配。

## 12. AI 问答模式

## 12.1 权限

访客：
- 不允许进入 AI 问答；
- 切换 AI 时应提示登录；
- 不发起 Provider 请求。

登录用户：
- 可以使用 AI 问答。

### 12.2 首页切换

AI 与搜索共用一个输入入口。

普通模式：

```text
[Google ▼] [ 搜索... ]
```

AI 模式：

```text
[AI ▼] [ Model ▼] [ 提问... ]
```

切回 Google/Bing 等立即退出 AI 模式。

每次重新打开 Searcher 首页默认普通搜索模式，不恢复上次 AI 模式。

### 12.3 提交后

提交 AI 问题后进入：

```text
/ask
```

首页不能展开成长篇 AI 聊天页面。

## 13. AI 问答页面

### 13.1 Desktop

```text
┌──────────────┬────────────────────────────────────┐
│ Conversation │ Provider / Model / New Chat       │
│ History      ├────────────────────────────────────┤
│              │                                    │
│ 今天         │ User                               │
│ 昨天         │ Assistant                          │
│ 7 天内       │                                    │
│ 更早         │                                    │
│              ├────────────────────────────────────┤
│              │       Message Composer             │
└──────────────┴────────────────────────────────────┘
```

左栏：
- 默认展开；
- 可折叠；
- 折叠状态保存为用户偏好。

Mobile：
- 历史记录进入 Drawer/Sheet；
- 对话区单列。

### 13.2 历史

自动分组：
- 今天；
- 昨天；
- 最近 7 天；
- 更早。

支持：
- 搜索；
- 重命名；
- 删除。

历史搜索第一版：
- 会话标题；
- 用户问题。

不索引所有 AI 回答。

### 13.3 模型选择

主输入区显示模型名称。

展开项显示：

```text
GPT-5.6
OpenAI

Model X
My Provider
```

模型必须来自 Provider `/models`。

如果 `/models` 获取失败：
- 不允许手填 Model ID；
- Provider 状态显示不可用于问答；
- 提示用户修复 Provider 配置。

### 13.4 默认模型优先级

```text
用户默认模型
  ↓
系统默认模型
  ↓
第一个当前允许且可用的模型
  ↓
无模型 → 显示“未配置模型”
```

### 13.5 Streaming

AI 回答默认流式显示。

中断时：
- 保留已生成内容；
- 显示“生成中断”；
- 提供“重试”。

不得悄悄自动切换其他 Provider / Model。

### 13.6 消息操作

Assistant：
- 复制；
- 重新生成。

重新生成：
- 不覆盖原回答；
- 形成 Assistant Variant；
- 用户可切换查看。

User：
- 复制。

不提供“编辑历史问题并创建分支”。

### 13.7 Markdown

AI 回答支持：
- Markdown；
- 表格；
- 代码块；
- 代码高亮；
- Copy。

v1 不做：
- Canvas；
- Artifact 工作区；
- 文件分析；
- 复杂工具调用 UI。

### 13.8 对话历史开关

开启：
- 保存对话与消息。

关闭：
- 当前对话仍可多轮；
- 不写入长期历史；
- 页面关闭或新建会话后不保留。

## 14. 固定 Web App 首页区域

### 14.1 默认数量

建议：
- Desktop：8–12；
- Mobile：4–8。

不是硬限制。

设置允许：

```text
首页最大显示
8 / 12 / 16 / 全部
```

超出后允许换行。

### 14.2 展示

首页只显示固定项，不显示分组标题。
固定图标区域与搜索框左边缘对齐；不显示悬浮省略号按钮。分组文件夹只在 Web App 面板的“全部”视图展示，不替代首页的固定图标。

每项：

```text
Icon
Name
```

Desktop icon 建议：
- 48–56px。

Mobile：
- 44–52px。

名称最多两行，超出省略。

### 14.3 大小设置

外观设置支持：
- 紧凑；
- 默认；
- 大图标。

### 14.4 排序

首页固定 Web App 使用一套排序，Desktop/Mobile 共用。

列数根据设备变化，但排序顺序不变。

```text

```

## 18. 添加 Web App

### 18.1 快速添加

```text
URL
↓
检测
↓
自动获取名称 / Icon
↓
保存
```

### 18.2 高级添加

字段：
- 名称；
- URL；
- 分组；
- Icon；
- 打开方式；
- 固定首页。

### 18.3 URL 安全

允许：
- http://
- https://

拒绝：
- javascript:
- data:
- file:
- 其他危险 scheme。

### 18.4 重复 URL

发现完全相同 URL：
- 提示“该网站已存在”；
- 仍允许用户继续添加。

因为可能使用不同：
- 名称；
- 图标；
- 分组。

### 18.5 URL 改变

修改 Web App URL 后：
- 不自动覆盖当前自定义 Icon；
- 提示“网址已改变，是否重新获取网站图标？”。

## 20. Icon 获取与管理

### 20.1 自动获取优先级

建议：

1. apple-touch-icon；
2. manifest icons；
3. `<link rel="icon">`；
4. favicon.ico；
5. 必要时其他可识别资源；
6. 仍无合适图标 → 字母占位图标。

### 20.2 Icon 来源

UI：

```text
网站资源
上传图片
图片 URL
AI 生成
```

“官方 Logo”只能归类为网站资源/用户上传，不把 AI 生成标记为官方原图。

### 20.3 AI Logo

风格示例：
- Minimal
- Glass
- 3D
- Clay
- Colorful
- Pixel
- Monochrome
- Neon

生成 2–4 个候选，用户选择其中一个作为当前 Icon。

未选择结果可短期缓存后清理。

### 20.4 当前 Icon

第一版每个 Web App 只记录一个当前 Icon。

生成历史不等于正式 Icon Variant 数据结构。

“置顶”和“固定主页”必须是两个独立状态：

```text
置顶
  → 便签管理区优先排序

固定主页
  → 首页显示
```

- 不回写数据库 title；
- 无正文时显示“无标题便签”。

## 25. 便签自动保存

不以 1 秒键盘事件保存。

流程：

```text
内容 input/change
↓
立即写入 IndexedDB Local Draft
↓
用户停止输入约 2.5–3 秒
↓
向 Server 同步
```

其他立即同步触发：
- Ctrl/Cmd + S；
- 编辑器失焦；
- 切换便签；
- 关闭编辑器。

### 25.1 保存状态显示

避免闪烁。

正常输入：
- 不持续显示“保存中”。

若同步耗时超过约 500–800ms：
- 才显示“保存中”。

成功：
- 弱化显示“已保存”。

失败：
- 明显显示“未同步 / 保存失败”。

---

## 26. Local Draft

草稿存 IndexedDB。

建议 Key 维度：

```text
user_id + note_id + device/browser scope
```

登出后：
- 未同步草稿不立即删除。

重新登录：
- 检测云端版本；
- 用户决定恢复/比较/放弃。

---

## 27. 便签版本与冲突

服务端每次合法保存维护版本号。

冲突时不得覆盖。

UI：

```text
检测到其他设备修改

云端版本              我的草稿
────────              ────────
内容                   内容

[复制草稿]
[使用云端版本]
[覆盖云端]
[合并后保存]
```

不得自动 AI Merge。

### 27.1 版本历史

用户可查看版本历史。

恢复旧版本：
- 当前内容保留为历史；
- 旧版本生成新的当前版本；
- 恢复行为本身可追踪。

### 27.2 快照频率

自动保存不能每 3 秒永久生成一个历史版本。

采用快照策略：
- 当前内容可正常更新；
- 每 10–30 分钟最多产生一个历史快照；
- 手动保存、冲突恢复等关键动作可以形成明确版本。

---

## 28. 会话失效时的草稿保护

若编辑便签过程中 Session 失效：

- 停止 Server 保存；
- Local Draft 继续保存；
- 不阻塞用户复制内容；
- 显示登录失效提示；
- 提供“复制全部草稿”；
- 登录恢复后比较云端与本地版本。

退出登录时若存在未保存便签：
- 必须提醒用户。

## 40. Toast 与反馈

统一使用 shadcn/ui 对应的 Sonner/Toast。

正常位置：
- Desktop 右上角或顶部中间；
- Mobile 避免与底部导航重叠。

语义：
- 成功：绿色语义；
- 错误：红色语义；
- 普通：中性色；
- Undo：明确 Action。

禁止：
- 每个 autosave 都弹 Toast；
- 快速连续闪烁“保存中/已保存”。

## 41. 同步状态

正常时：
- 不显示全局同步 Icon。

只有异常：
- 右上角出现“同步失败”状态；
- 点击查看哪些内容未同步。

本地草稿存在但 Server 失败时：
- 用户仍可继续编辑；
- 后台网络恢复后自动重试；
- 不使用阻塞式 Modal。

## 42. 实时同步前端行为

Searcher 使用 REST + SSE/轻量事件。

### Notes
Server 保存成功后发：

```text
note.updated
note_id
version
```

其他设备：
- 正在编辑同 Note → 不直接覆盖；
- 标记远端版本变化；
- 保存时进入冲突流程。

### Web App
拖拽过程中：
- 不发请求。

松手：
- 一次性提交最终排序。

### Preferences
当前设备：
- 立即生效；
- 同步 Server。

其他设备：
- 不强制瞬间改变正在使用的页面；
- 可提示“设置已在其他设备更新”；
- 下次导航/刷新应用。

## 53. 2K / 4K 行为

2K / 4K 不是简单“放大所有东西”。

应：
- 搜索容器最多约 1080px；
- 增加周围留白；
- 固定 App 可适度增加列数；
- 固定便签自由区域变大；
- 字体保持合理可读尺寸；
- Header 仍贴近可视边缘；
- Bottom Nav 不无限拉宽。

验收必须覆盖：
- 1920×1080；
- 2560×1440；
- 3840×2160。

## 54. Mobile 行为

建议至少覆盖约 360–430px 宽度。

Mobile 必须：
- 搜索输入可完整使用；
- Engine/Model selector 不挤压输入框；
- Web App 使用 Grid；
- Note 使用 Grid/List；
- 无自由重叠便签；
- Drawer 可滑动关闭；
- Toast 不遮挡底部导航；
- AI 历史通过 Drawer 打开。

## 55. Accessibility

至少做到：
- 所有 Icon-only Button 有 aria-label；
- Tab 顺序合理；
- Dropdown/Command 可键盘导航；
- focus ring 清晰；
- Dialog/Drawer 打开后管理焦点；
- Esc 能关闭；
- 红/绿状态不能只靠颜色解释，Tooltip/可访问文本需表达状态；
- Dark Mode 保证基本对比度；
- 拖拽操作应存在非拖拽替代操作（至少在管理模式中支持上下移动或可键盘排序）。

- Providers / Models
- Preferences
- Trash
- Admin Data

### Local UI State

- Drawer 开关；
- Dialog 开关；
- 当前 Tab；
- 当前拖拽；
- Hover；
- 当前搜索/AI输入；
- 临时选择状态。

### IndexedDB

- 搜索引擎资源连接状态；
- 访客偏好；
- Note Local Draft；
- 必要的弱离线缓存。

禁止将所有状态放入一个庞大全局 Store。

## 57. 后端技术契约（前端需感知的部分）

已确认基础方向：

```text
Runtime
Deno

Database
SQLite + WAL

ORM
Drizzle ORM

Search
SQLite FTS5

Storage
Local filesystem + SQLite metadata

Realtime
REST + SSE / lightweight events

AI
Browser → Searcher Backend → OpenAI-Compatible Provider
```

前端不得直接把 API Key 发往第三方 Provider。

## 58. FTS5 使用场景

Web App：
- name；
- URL。

Notes：

- Markdown 正文。

AI History：
- conversation title；
- user question。

搜索结果应高亮命中片段，但不得把 Markdown HTML 原样注入 DOM。

## 61. 开发完成定义

前端不能以“页面能打开”为完成标准。

必须同时满足：

1. Desktop / Mobile 响应式完整；
2. Light / Dark / System 正常；
3. 至少一种额外 Style 可验证；
4. 搜索 / AI 两种模式逻辑明确；
5. Web App CRUD + 分组 + 固定 + 排序完整；
6. Notes Markdown + Draft + Autosave + Conflict + Version History 完整；
7. 用户/访客权限正确；
8. AI 未登录拦截正确；
9. Admin 页面前后端权限一致；
10. 所有关键 Loading / Empty / Error 状态存在；
11. IndexedDB 草稿和资源可达状态按约定工作；
12. SSE 断线不会导致数据丢失；
13. 所有删除操作符合软删除/Undo/回收站规则；
14. 2K / 4K 不出现主内容过小或异常拉伸；
15. 所有普通 UI 组件遵循 shadcn/ui 体系。

## 62. Agent 实现提示

给前端 Coding Agent 时应明确：

> 不要自行“优化”产品边界。  
> 不要将 Searcher 首页改造成 Dashboard。  
> 不要为了展示更多功能而削弱搜索框视觉焦点。  
> 不要把便签 autosave 做成高频 Toast。  
> 不要让 AI 自动替代搜索。  
> 不要在 Session 失效或版本冲突时覆盖 Local Draft。  
> 不要为方便开发绕过权限或让 Browser 直接持有 Provider API Key。  
> 对未定义行为优先保持最小实现，而不是扩展功能。
