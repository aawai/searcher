# Searcher 前端实现指南

> 文档用途：指导 Searcher v1 的前端
> UI、交互、状态管理、响应式布局、异常处理与前后端边界实现。\
> 本文以已确认需求为准；未在本文中定义的能力不应自行扩展为 v1 必需功能。\
> UI 基础组件必须优先使用 **shadcn/ui**，图标建议使用 Lucide；拖拽/排序等
> shadcn/ui 不直接提供的能力可使用专门库实现，但最终视觉和交互应与 shadcn/ui
> 体系一致。

---

## 1. 产品定位

Searcher 是一个 **Search First 的中文个人搜索主页 / 起始页**。

首页的第一视觉焦点始终是搜索框。个人内容（Web
App、便签）围绕搜索存在，但不能让首页演变成传统 Dashboard。

### 1.1 五条核心设计原则

1. **Search First**\
   搜索框始终是首页第一视觉焦点。

2. **Personal, not Dashboard**\
   收藏、便签、设置属于搜索主页的辅助能力，不能抢占搜索框的主视觉地位。

3. **Local-first Deployment**\
   核心功能基于 Deno + SQLite + 本地文件即可运行，不依赖第三方云基础设施。

4. **Explicit AI**\
   AI 问答必须由用户明确切换进入，不得在普通搜索中自动介入或替换搜索结果。

5. **No Silent Data Loss**\
   草稿、版本冲突、同步失败、登录会话失效时，不得静默覆盖或丢弃用户内容。

## 5. 响应式与尺寸

### 5.1 搜索主区域

不要使用固定 720–840px 宽度。

Desktop 建议：

```css
width: clamp(680px, 52vw, 1080px);
```

目标：

- 1080p：保持集中；
- 2K：自然放大；
- 4K：最多约 1080px，不无限拉伸；
- 超宽屏主要增加留白而不是无限放大搜索框。

Mobile：

```css
width: calc(100vw - 32px);
```

### 5.2 垂直位置

搜索主区域位于视口高度约 30%–35%，不要严格居中。

目的：

- 下方为 Web App 与固定便签保留空间；
- 首页打开后搜索仍然第一眼可见。

### 5.3 搜索框圆角

圆角属于 Style 的一部分：

- Default：中大圆角；
- Minimal：偏小；
- Soft：较大；
- Glass：较大；
- Capsule：允许完整胶囊化。

不可把胶囊化写死为唯一样式。

## 8. 搜索框

## 8.1 普通搜索模式

Desktop 逻辑结构：

```text
[Engine ▼] [ Search Input                              ] [Search]
```

视觉上可将按钮整合在同一容器。

搜索引擎：

- Google
- Bing
- 百度
- DuckDuckGo

### 8.2 搜索引擎选择器

常态仅显示：

- Logo；
- 小型下拉箭头。

展开后显示：

```text
Google       ●
Bing         ●
百度         ●
DuckDuckGo   ●
────────────────
重新检测
设为默认
```

圆点：

- 绿色：当前设备最近一次资源连接检测成功；
- 红色：最近一次检测未成功。

不得显示“搜索服务正常/异常”等结论。

### 8.3 当前设备可达性

约束：

- 检测完全在浏览器执行；
- 服务端不参与；
- 结果存 IndexedDB；
- 不同设备结果独立；
- 检测是启发式资源连接检测；
- 不等价于搜索服务可用性。

建议记录：

```ts
{
    engineId, reachable, checkedAt, latency;
}
```

菜单主视图只显示红/绿点。

Tooltip/详情可以显示：

- 最近检测时间；
- 耗时。

### 8.4 重新检测

底部“重新检测”：

- 并发检测所有启用引擎；
- 检测期间显示 Spinner；
- 完成后更新 IndexedDB。

允许针对单个搜索引擎重新检测。

### 8.5 默认搜索引擎与临时切换

用户在首页临时切换引擎：

- 只影响当前搜索；
- 不自动修改默认引擎。

只有：

- 设置页修改；
- 或菜单中明确“设为默认”

才改变默认值。

## 9. 搜索行为

### 9.1 URL Template

默认搜索引擎通过 URL Template 执行搜索。

例如：

```text
https://www.google.com/search?q={query}
```

前端提交前：

- URL encode query；
- 不允许危险协议；
- 不在客户端执行字符串脚本。

### 9.2 打开方式

用户偏好：

- 当前页；
- 新标签页。

快捷行为：

```text

  → 按用户默认设置

Ctrl/Cmd + Enter
  → 强制新标签页
```

### 9.3 键盘快捷键

至少支持：

```text
/
  聚焦搜索框

Ctrl/Cmd + K
  聚焦搜索框

Esc
  关闭弹窗 / 退出当前轻量编辑状态
```

## 11. 搜索建议

v1 接入：

- Google 搜索联想能力；
- Bing 搜索联想能力；
- 本地搜索历史（用户开启后）；

1. 本地高相关结果；
2. 当前引擎联想；
3. Web App 匹配。

## 12. AI 问答模式

## 12.1 权限

访客：

- 不允许进入 AI 问答；
- 切换 AI 时应提示登录；
- 不发起 Provider 请求。

登录用户：

- 可以使用 AI 问答。

### 12.2 首页切换

AI 与搜索共用一个输入入口。

普通模式：

```text
[Google ▼] [ 搜索... ]
```

AI 模式：

```text
[AI ▼] [ Model ▼] [ 提问... ]
```

切回 Google/Bing 等立即退出 AI 模式。

每次重新打开 Searcher 首页默认普通搜索模式，不恢复上次 AI 模式。

### 12.3 提交后

提交 AI 问题后进入：

```text
/ask
```

首页不能展开成长篇 AI 聊天页面。

### 13.1 Desktop

```text
│              │                                    │
```

左栏：

- 默认展开；
- 可折叠；
- 折叠状态保存为用户偏好。

Mobile：

- 历史记录进入 Drawer/Sheet；
- 对话区单列。

### 13.2 历史

自动分组：

- 今天；
- 昨天；
- 最近 7 天；
- 更早。

支持：

- 搜索；
- 重命名；
- 删除。

历史搜索第一版：

- 会话标题；
- 用户问题。

不索引所有 AI 回答。

### 13.3 模型选择

主输入区显示模型名称。

展开项显示：

```text
GPT-5.6
OpenAI

Model X
My Provider
```

模型必须来自 Provider `/models`。

如果 `/models` 获取失败：

- 不允许手填 Model ID；
- Provider 状态显示不可用于问答；
- 提示用户修复 Provider 配置。

### 13.4 默认模型优先级

```text
用户默认模型
  ↓
系统默认模型
  ↓
第一个当前允许且可用的模型
  ↓
无模型 → 显示“未配置模型”
```

### 13.5 Streaming

AI 回答默认流式显示。

中断时：

- 保留已生成内容；
- 显示“生成中断”；
- 提供“重试”。

不得悄悄自动切换其他 Provider / Model。

### 13.6 消息操作

Assistant：

- 复制；
- 重新生成。

重新生成：

- 不覆盖原回答；
- 形成 Assistant Variant；
- 用户可切换查看。

User：

- 复制。

不提供“编辑历史问题并创建分支”。

### 13.7 Markdown

AI 回答支持：

- Markdown；
- 表格；
- 代码块；
- 代码高亮；
- Copy。

v1 不做：

- Canvas；
- Artifact 工作区；
- 文件分析；
- 复杂工具调用 UI。

### 13.8 对话历史开关

开启：

- 保存对话与消息。

关闭：

- 当前对话仍可多轮；
- 不写入长期历史；
- 页面关闭或新建会话后不保留。

## 15. APP Bottom Sheet / Drawer

首页底部导航仅有：

```text
APP          便签
```

搜索页本身就是默认页面，不需要“首页”Tab。

### 15.1 Desktop

点击 APP：

- 打开底部大面板；
- 默认约 65vh；
- 可调整到约 40% / 65% / 90%（与便签面板保持一致的全屏与高度展开逻辑）。

### 15.2 Mobile

使用 Bottom Drawer。

### 15.3 默认打开状态

每次重新打开 APP 面板：

- 进入“全部”视图（默认展示全部应用与文件夹，取消分组筛选按钮与管理模式按钮）；
- 文件夹可通过顶部“文件夹”管理按钮直接进入管理维护。

### 15.4 内容结构

```text
APP
────────────────────────
[搜索网站]    [+ APP] [文件夹]

App Grid / List (默认展示全部)
```

“全部”视图使用统一基础 Cell + First-Fit Occupancy Grid。APP 和小文件夹各占
1×1，大文件夹占 2×2；用户保存的是 APP 的 canonical sort_order 和文件夹的
folder_size（旧数据默认 small），不保存响应式 col/row。 先按 sort_order
折叠分组为一个 tile；只对当前搜索/分类可见的顶层
tiles，从左到右、从上到下扫描空闲 cell，逐格标记 1×1 或 2×2 占位。CSS Grid
根据计算出的 col/row/span 定位，不依赖 grid-auto-flow:dense、Masonry
或绝对坐标。大文件夹右侧第二行允许继续排
APP，多个大文件夹和行尾都按同一规则处理。 ResizeObserver
监听实际桌面容器宽度，以 cellWidth / columnGap 推导列数（至少
2），尺寸变化只重算 derived layout；40% / 65% / 90%
改的是面板高度，不直接改变列数。cellHeight
包含图标、间距和最多两行名称，隐藏名称时切换更紧凑的行高及 rowGap；大文件夹的 2
行高度严格等于 2×cellHeight + rowGap。 小文件夹的 2×2 缩略图与普通 APP
对齐；大文件夹用独立 3×3 preview（最多 9 个，超出显示 +N）。文件夹的 Grid Item
与 APP 共用列宽、行高及 gap：小文件夹宽 1 列，大文件夹宽 2×列宽+列
gap；背景独立按宽度保持 1:1，名称在背景下方，间距与 APP 图标到名称的 6px
一致。预览图标在独立固定轨道中从左上角依次排列，横纵间距相同，不随背景拉伸；居中的图标阵列保留对称边距。仅显示图标时保留
APP
原有行距，若两行占位高度小于跨列宽度，则文件夹背景等比收至可容纳的正方形，不溢出占位。大文件夹预览
APP
点击直达网站并阻止文件夹打开；点背景或名称打开完整内容。点击文件夹外部收起，不关闭
Web App 面板。 排序沿用 dnd-kit：pointerWithin 优先、closestCenter
回退；拖拽原位保留占位，DragOverlay 按真实 1×1 / 2×2 尺寸显示，不对不等大 rect
做临时交换；drop 后重排 canonical order 并向 server
提交。过滤拖拽只替换可见槽位，隐藏 APP 的顺序不被覆盖。

“未分组”为虚拟分组：

```text
group_id = null
```

数据库中不创建名为“未分组”的实体。

## 16. Web App 分组

支持：

- 创建；
- 重命名；
- 排序；
- 切换小文件夹 / 大文件夹（文件夹管理或右键菜单），刷新后保持；
- 删除。

规则：

- Web App 可以没有分组；
- 一个 Web App 最多属于一个分组；
- 删除分组时 App 不删除；
- App 自动变为未分组。

固定首页属性与分组完全独立。

  `sortOrder`。

### 21.2 便签列表 Masonry 瀑布流布局与双层拖拽隔离架构

便签面板抽屉列表采用真实的 Masonry / 瀑布流布局算法，严格避免使用造成 DOM 脱节的
CSS columns 或产生随机乱序的 `grid-auto-flow: dense`：

1. **最短列贪心定位算法（Shortest-column）**：
   - 容器宽度监听：通过原生 `ResizeObserver` 动态监听便签容器元素真实
     `clientWidth`（精确感知纵向滚动条带来的内容宽度扣减，禁止依赖
     `window.innerWidth`）；
   - 响应式自适应列宽：列数由
     `Math.floor((containerWidth + gap) / (minColumnWidth + gap))`
     结合上限确定（大屏 3 列 / 抽屉面板 2 列 / 窄屏移动端 1 列，基准列宽
     `minColumnWidth = 245px`，`gap = 16px`）；
   - 最短列补齐：卡片高度独立，后续卡片按当前各列累计高度最小者贪心入列，卡片下边缘紧密衔接，彻底消除传统
     CSS Grid 同行最高卡片拉伸整行造成的死区空白；
   - 容器滚动高度：容器真实高度计算为卡片底边最大坐标 `maxBottom`，严格匹配抽屉
     `.sheet-content` 的滚动条高度，保证底部最后一张卡片完整显示无截断。
2. **动态高度防抖与死循环防护**：
   - 监听每个卡片 DOM 节点的渲染高度，维护 `heightMap`；
   - 仅当高度变化阈值 $\ge 1\text{px}$ 时标记变更，并通过
     `requestAnimationFrame` 异步批处理触发重排，杜绝 ResizeObserver loop
     告警与重复渲染。
3. **双层 DOM 架构隔离 Transform**：
   - 外层 Masonry Item Wrapper：负责卡片静态绝对定位坐标
     `position: absolute; width: ${colWidth}px; transform: translate3d(x, y, 0);`
     以及重排平滑过渡 `transition: transform 200ms ease`；
   - 内层 Sortable Wrapper：承接 dnd-kit 的
     `useSortable`、`setNodeRef`、拖拽手柄属性与事件；
   - 排序策略隔离：`SortableContext` 显式设置 `strategy={() => null}`，禁止
     dnd-kit 内置网格计算覆盖或扭曲瀑布流真实坐标；
   - 拖拽过程采用 `DragOverlay`
     渲染卡片镜像副本，原卡片半透明占位维持瀑布流骨架稳定；
   - 碰撞检测采用组合策略（`pointerWithin` 优先，未命中时回退至
     `closestCenter`），避免远距离列误判定；拖拽释放时基于目标卡片中心偏上/偏下确定前后插入位置，并受置顶分区严格约束。

## 29. 首页固定便签

### 29.1 Desktop 全视口自由画布

固定便签属于视口全屏自由画布层，解除搜索框下方流式容器限制：

- 支持在全屏幕视口内任意位置自由拖动；
- 允许重叠，点击或拖拽任意便签自动将其 `z-index` 提升为最高并持久化；
- 拖拽松手时若遮挡主搜索框执行软回弹避让。

### 29.2 固定便签的两种显示模式与紧凑靠右操作栏

首页固定便签与抽屉便签卡片支持两种显示模式：

1. **展开（Expanded）**：展示便签标题、轻量 Markdown 格式正文与操作栏；
2. **简单极简模式（Compact /
   Simple）**：空间占用最小化，仅显示标题（或无标题时展示首行摘要），不渲染正文大块
   Markdown，释放主视觉空间；移动端下折叠状态自适应紧凑收缩。

操作按钮与排版优化：

- 卡片外层的“展开/折叠”与“更多”操作按钮尺寸精简为 24px×24px
  紧凑图标按钮，严格靠右对齐；
- 操作栏采用绝对定位浮层，非 hover/focus
  状态下淡出隐藏，此时便签标题与预览文字完全占满卡片可用宽度，文字展示面积提升
  40% 以上，无提前截断；
- 鼠标悬停（Hover）或获得焦点时，右侧操作按钮平滑显现，兼顾极致文本信息密度与完整操作便利。

### 29.3 点击行为

普通点击：激活并提升层级；双击便签切换“展开”与“折叠”状态。
编辑：通过“更多”下拉菜单中的“编辑便签”进入详情编辑。

### 29.4 搜索区域避让

便签允许经过搜索区域。

松手时若大面积遮挡主搜索框：

- 进行软回弹；
- 移到最近合理位置。

不做完全刚性的禁区。

### 29.5 Mobile

不使用自由 XY 坐标。

采用：

- Grid；
- 或纵向列表。 同步：
- 内容；
- 颜色；
- 固定状态；
- 排序。

不同步 Desktop XY 坐标。

- Toast 提供撤销；
- 回收站保留 30 天。

回收站：

- 恢复；
- 永久删除；
- 清空。

### 39.2 AI 会话

不进入普通回收站。

删除后：

- 短时间 Undo；
- 服务端延迟清理；
- 不在“数据与同步 → 回收站”长期展示。

---

## 40. Toast 与反馈

统一使用 shadcn/ui 对应的 Sonner/Toast。

正常位置：

- Desktop 右上角或顶部中间；
- Mobile 避免与底部导航重叠。

语义：

- 成功：绿色语义；
- 错误：红色语义；
- 普通：中性色；
- Undo：明确 Action。

禁止：

- 每个 autosave 都弹 Toast；
- 快速连续闪烁“保存中/已保存”。

---

## 41. 同步状态

正常时：

- 不显示全局同步 Icon。

只有异常：

- 右上角出现“同步失败”状态；
- 点击查看哪些内容未同步。

本地草稿存在但 Server 失败时：

- 用户仍可继续编辑；
- 后台网络恢复后自动重试；
- 不使用阻塞式 Modal。

---

## 42. 实时同步前端行为

Searcher 使用 REST + SSE/轻量事件。

### Notes

Server 保存成功后发：

```text
note.updated
note_id
version
```

其他设备：

- 正在编辑同 Note → 不直接覆盖；
- 标记远端版本变化；
- 保存时进入冲突流程。

### Web App

拖拽过程中：

- 不发请求。

松手：

- 一次性提交最终排序。

### Preferences

当前设备：

- 立即生效；
- 同步 Server。

其他设备：

- 不强制瞬间改变正在使用的页面；
- 可提示“设置已在其他设备更新”；
- 下次导航/刷新应用。

---

## 43. 访客行为

访客可以：

- 搜索；
- 切换搜索引擎；
- 搜索引擎可达检测；
- 修改 Theme；
- Style；
- Wallpaper；
- 搜索结果打开方式。

访客不可以：

- Web App；
- 便签；
- AI 问答；
- 云端同步。

访客本地偏好：

- IndexedDB / Local Storage。

登录后：

- 默认使用云端配置覆盖本地配置（变更注记：根据 2026-09-25
  决策，偏好属于外观配置，登录后以云端配置为准，不弹出选项让用户选择谁覆盖谁；便签草稿等核心数据仍严格执行
  No Silent Data Loss）；
- 不弹出冲突选择弹窗。

## 44. 登录与注册

首页点击“登录”打开居中 Dialog。

登录：

```text
登录 Searcher

用户名 / 邮箱
密码
[保持登录]

[登录]

没有账号？注册
```

注册在同 Dialog 中切换。

管理员可以关闭公开注册：

- 此时注册入口隐藏或显示“注册已关闭”。

## 45. Session / 设备 UI

默认：

- 普通登录 7 天；
- “保持登录”30 天。

账户页可查看登录设备：

- 当前设备；
- 浏览器；
- 创建时间；
- 最后活动时间。

不采集精确位置。

操作：

- 退出此设备；
- 退出其他设备。

---

## 46. 管理员重置密码后的前端行为

管理员重置密码：

- 目标用户所有 Session 失效；
- 下次登录使用临时密码；
- 首次登录强制修改密码。

任何已打开页面：

- API 返回失效状态后进入重新登录流程；
- 若正在编辑便签必须先保护 Local Draft。

---

## 47. 搜索主页软离线

不做完整 Offline-first PWA，但支持弱离线：

可继续：

- 已加载 UI；
- Local Draft 便签编辑；
- Web App 本地缓存展示；
- 普通 URL 搜索跳转（视浏览器网络实际情况）。

不可用：

- 登录同步；
- Server 保存；
- AI；
- Server 数据刷新。

离线恢复：

- 自动重试未同步草稿；
- 不能静默覆盖远端新版本。

## 49. Loading / Skeleton

以下场景应使用 Skeleton/Spinner：

- 用户状态恢复；
- Web App 列表；
- Notes 列表；
- AI 历史；
- Provider Models；
- Admin Users；
- Backup 操作。

不要用全屏 Spinner 阻塞整个应用，除非是首次系统初始化或完整备份恢复。

## 50. 错误边界

至少处理：

- API 网络错误；
- Session 失效；
- 无权限；
- AI Provider 不可用；
- `/models` 获取失败；
- AI streaming 中断；
- Web App icon 获取失败；
- Wallpaper 上传失败；
- Note version conflict；
- IndexedDB 不可用；
- SSE 断线；
- 搜索联想 API 失败；
- 第三方搜索引擎资源探测失败。

所有错误必须：

- 有可理解的用户文案；
- 有重试或退出路径；
- 不清空用户当前输入。

## 52. 视觉设计规则

### 52.1 层级

视觉优先级：

```text
搜索框
  >
Searcher 标题 / 当前任务
  >
固定 Web App
  >
固定便签
  >
底部导航
  >
辅助设置与状态
```

### 52.2 便签

默认：

- 低饱和；
- 轻边框或无强边框；
- 轻阴影；
- hover 增强；
- 不抢搜索框焦点。

### 52.3 Motion

使用短促、克制动画：

- Dropdown；
- Drawer；
- Dialog；
- App reorder；
- Note expand。

避免：

- 大幅弹跳；
- 长时间背景动效；
- 保存状态闪烁；
- AI token 渲染造成页面整体跳动。

## 53. 2K / 4K 行为

2K / 4K 不是简单“放大所有东西”。

应：

- 搜索容器最多约 1080px；
- 增加周围留白；
- 固定 App 可适度增加列数；
- 固定便签自由区域变大；
- 字体保持合理可读尺寸；
- Header 仍贴近可视边缘；
- Bottom Nav 不无限拉宽。

验收必须覆盖：

- 1920×1080；
- 2560×1440；
- 3840×2160。

---

## 54. Mobile 行为

建议至少覆盖约 360–430px 宽度。

Mobile 必须：

- 搜索输入可完整使用；
- Engine/Model selector 不挤压输入框；
- Web App 使用 Grid；
- Note 使用 Grid/List；
- 无自由重叠便签；
- Drawer 可滑动关闭；
- Toast 不遮挡底部导航；
- AI 历史通过 Drawer 打开。

---

## 55. Accessibility

至少做到：

- 所有 Icon-only Button 有 aria-label；
- Tab 顺序合理；
- Dropdown/Command 可键盘导航；
- focus ring 清晰；
- Dialog/Drawer 打开后管理焦点；
- Esc 能关闭；
- 红/绿状态不能只靠颜色解释，Tooltip/可访问文本需表达状态；
- Dark Mode 保证基本对比度；
- 拖拽操作应存在非拖拽替代操作（至少在管理模式中支持上下移动或可键盘排序）。

## 57. 后端技术契约（前端需感知的部分）

已确认基础方向：

```text
Runtime
Deno

Database
SQLite + WAL

ORM
Drizzle ORM

Search
SQLite FTS5

Storage
Local filesystem + SQLite metadata

Realtime
REST + SSE / lightweight events

AI
Browser → Searcher Backend → OpenAI-Compatible Provider
```

前端不得直接把 API Key 发往第三方 Provider。

## 58. FTS5 使用场景

Web App：

- name；
- URL。

Notes：

- title；
- Markdown 正文。

AI History：

- conversation title；
- user question。

搜索结果应高亮命中片段，但不得把 Markdown HTML 原样注入 DOM。

- 不制造错误；

## 60. 不属于 v1 的能力

除非需求后续重新开启，否则不要擅自加入：

- 多分组归属 / Tag System；
- Nested Group；
- 复杂团队协作；
- 便签附件；
- 任意 HTML；
- AI 自动搜索接管；
- AI 消息树形分支编辑；
- 用户手动填写 Provider Model ID；
- 个人数据导出；
- 完整 Offline-first PWA；
- AI Canvas / Artifacts；
- AI 文件分析；
- 搜索首页时钟/日期默认组件；
- 自动 Provider failover。

## 61. 开发完成定义

前端不能以“页面能打开”为完成标准。

必须同时满足：

1. Desktop / Mobile 响应式完整；
2. Light / Dark / System 正常；
3. 至少一种额外 Style 可验证；
4. 搜索 / AI 两种模式逻辑明确；
5. Web App CRUD + 分组 + 固定 + 排序完整；
6. Notes Markdown + Draft + Autosave + Conflict + Version History 完整；
7. 用户/访客权限正确；
8. AI 未登录拦截正确；
9. Admin 页面前后端权限一致；
10. 所有关键 Loading / Empty / Error 状态存在；
11. IndexedDB 草稿和资源可达状态按约定工作；
12. SSE 断线不会导致数据丢失；
13. 所有删除操作符合软删除/Undo/回收站规则；
14. 2K / 4K 不出现主内容过小或异常拉伸；
15. 所有普通 UI 组件遵循 shadcn/ui 体系。

## 62. Agent 实现提示

给前端 Coding Agent 时应明确：

> 不要自行“优化”产品边界。\
> 不要将 Searcher 首页改造成 Dashboard。\
> 不要为了展示更多功能而削弱搜索框视觉焦点。\
> 不要把便签 autosave 做成高频 Toast。\
> 不要让 AI 自动替代搜索。\
> 不要在 Session 失效或版本冲突时覆盖 Local Draft。\
> 不要为方便开发绕过权限或让 Browser 直接持有 Provider API Key。\
> 对未定义行为优先保持最小实现，而不是扩展功能。
