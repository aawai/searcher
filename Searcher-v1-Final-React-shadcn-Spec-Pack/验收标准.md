# Searcher 成品验收标准

> 用途：用于对 Searcher v1
> 的最终成品进行产品、UI、交互、权限、稳定性与边界验收。\
> 本文按“可执行验收”编写。每条标准应能够通过人工操作、浏览器开发者工具或自动化测试明确判断通过/失败。

---

## 1. 验收原则

### 1.1 结果判定

每条用例状态：

- **PASS**：行为与标准完全一致；
- **FAIL**：功能缺失、行为错误、存在数据覆盖风险或 UI 明显不符合约束；
- **BLOCKED**：因外部 Provider、第三方接口或部署环境不可用无法执行；
- **N/A**：当前构建明确不包含该条件且产品规格允许。

### 1.2 严重级别

- **P0**：数据丢失、安全/权限绕过、核心搜索不可用、管理员权限泄露；
- **P1**：主要业务功能不可用或与已确认交互相反；
- **P2**：非核心功能错误、响应式明显异常；
- **P3**：轻微视觉、文案、动效问题。

发布要求建议：

- P0 = 0；
- P1 = 0；
- P2 必须有明确可接受记录；
- P3 可进入后续修复。

# A. 产品原则验收

## A-001 Search First

**步骤**

1. 打开首页；
2. 分别在 1080p、2K、4K 和 Mobile 查看。

**预期**

- 搜索框是最显著的交互元素；
- Web App、便签、底部导航均为次级视觉；
- 首页不得呈现传统 Dashboard 卡片墙效果。

**严重级别：P1**

---

## A-002 AI 不自动介入普通搜索

**步骤**

1. 保持 Google/Bing/百度/DDG 普通搜索模式；
2. 输入自然语言问题并回车。

**预期**

- 按当前搜索引擎执行搜索；
- 不自动切换 AI；
- 不在首页生成 AI 回答。

**严重级别：P0**

---

## A-003 No Silent Data Loss

**步骤**

1. 编辑便签；
2. 制造断网、Session 失效、跨设备冲突之一；
3. 继续输入。

**预期**

- 当前输入仍存在；
- Local Draft 可恢复/复制；
- 不被云端旧内容静默覆盖。

**严重级别：P0**


## A-004 服务异常与离线重试提示

**步骤**

1. 制造服务端 503 或网络离线；
2. 访问首页或刷新页面；
3. 恢复服务并点击“重试”按钮。

**预期**

1. 当服务端不可达或返回 503 时，顶部展示非阻断提示条“服务暂不可用，部分功能可能受限”；
2. 提示条内提供基于 shadcn `Button`（`outline`，`sm`）的“重试”操作；
3. 搜索框与界面仍可交互，不白屏、不阻塞匿名本地功能；
4. 恢复网络后点击“重试”，提示条平滑消除；
5. 确认为匿名的 401 响应不误报连接错误。

**严重级别：P1**

## B-008 设置操作卡片自适应

**环境**：375px、390px、640px、768px、1280px。

## B-009 Design Lab 稳定性与尺寸防御

**环境**：`/design-lab`，桌面与 390px 移动端。

**预期**：

1. 默认“主页”预览静置 2 秒以上，控制台 0 错误，不触发 `Maximum update depth exceeded`；
2. 在“搜索”、“APP”、“便签”、“导航与 Sheet”、“主页”之间连续切换 Tab，交互平滑且无死循环重渲染；
3. 390px 视口下文档宽度严格等于 390px，消除搜索预览组件导致的横向溢出（如 397px）。

**严重级别：P1**

---

## B-010 Slider 控件与可访问性

**环境**：`/settings/appearance` 浅色与深色模式。

**预期**：

1. 标量输入（如搜索框透明度、遮罩比例、模糊半径、灰度比例）各自仅渲染 1 个可操作 `Thumb`；
2. 仅当明确传入数组范围值时才按端点数量渲染多个 `Thumb`；
3. 每个 `Thumb` 内部生成的 `<input type="range">` 均具备与设置项匹配的明确 `aria-label`，无障碍树中名称完整可读；
4. 键盘方向键调节、触屏拖拽与受控状态更新功能正常。

**严重级别：P1**

## L-005 Occupancy Grid 与混合尺寸

在“全部”视图创建普通
APP、小文件夹（1×1）和大文件夹（2×2），至少两个大文件夹；将大文件夹放在行首、行尾附近和列表中间。

预期：逻辑 Cell 无重叠/越界；10 列时行首大文件夹右侧的第二行继续放 APP；普通 APP
列宽、行高和行距不因文件夹变化。大文件夹 Grid Item 宽恰为两列宽加一段
columnGap，背景与 Grid Item 左上角对齐并呈 1:1，名称位于背景下方且相隔与 APP
图标到名称相同的 6px；小文件夹亦对应一列宽。内部小图标按固定 2×2/3×3
轨道和相等的横纵 gap 排列，尺寸不随背景拉伸。仅显示图标若 2
行高度不足跨列宽，背景收至占位可容纳的正方形而不改变普通 APP
行距。尺寸切换后释放的 Cell 由后续 APP 补位。大文件夹预览 3×3
最多九个，超出显示数量提示；预览 APP 点击直达网站而背景/名称点击打开
Folder。过滤及分类只让可见顶层 tiles 占位。

ResizeObserver 随容器宽度重算列数；面板的 40%/65%/90%
是高度，不要求列数改变。拖动 APP/小文件夹/大文件夹后按 canonical sort_order
重排，刷新后顺序和 folder_size 保持，Folder CRUD 及加入/移出/内部排序不回归。
